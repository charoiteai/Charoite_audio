# Audit notes — 2026-10-10

Review performed via GitHub API on `main` (SHA `5149770552b2b49c8b48dec12ad44a8351028cbf`).

## Summary

Codebase is mature, carefully engineered, and heavily commented with references to previous audit rounds (DS, GLM, Opus, Sonnet, etc.). Strong emphasis on:

- Local-first / privacy (no silent cloud calls)
- Atomic writes for graph nodes (`safe_write`)
- Live-meeting priority over background work (`live_gate` + flock)
- Resilience (broad but intentional `except Exception` in non-critical loops, with status emission)
- Resource contention management (model leases, busy retries, priority gates)

**No critical bugs** were identified in the sampled high-risk paths:

- `src/charoite_graph/safe_write.py` — atomic tmp+replace, expect-gates, metadata carry-over, symlink handling. Well-documented race conditions.
- `src/file_locks.py` — careful distinction between BlockingIOError (busy) vs OSError (no flock support). Shared lock for graph writers.
- `src/live_gate.py` — single source of truth for “meeting is live” via daemon.lock; night caps; finite-cap validation.

## Structure (high level)

- `src/daemon.py` — central process, NDJSON protocol, many concurrent loops (STT, hints, theses, minutes, déjà vu, names…).
- `src/charoite_graph/` — graph model, search, dossiers, safe writes.
- `app/` — Swift macOS app (thin client over daemon).
- `app-ios/`, `app-android/` — recording companions that write into the same markdown graph.
- Extensive `docs/` and CI (CodeQL, supply-chain, release-please).

## Observations / possible follow-ups for Claude review

1. **Broad `except Exception`** — used intentionally in auxiliary loops so a single failure does not kill the meeting. Status is emitted on change. Worth confirming no critical path is accidentally swallowing errors that should abort.

2. **Daemon size** — `daemon.py` is large (~270 KB). The comment style shows it has been through many incremental hardening passes. A future modularization (extract loops) could improve navigability without changing behavior.

3. **iCloud / network FS** — many comments address iCloud Drive quirks (zero-byte files, flock behavior, copy2 side-effects). The `safe_write` + `copy_if_changed` design looks solid; worth a dedicated stress test if graph lives on iCloud.

4. **Decision gate** — currently shadow-only. The plan to promote it based on measured data is sound.

5. **No open issues** at time of review.

## Recommendation

Safe to continue development. Suggested next step for a deeper pass: focused review of `graph_updater.py` + nightly dossier path, and the Swift UI ↔ daemon protocol contract.

# `packages/` — метаданные дистрибутивов Чароита

Каталог под метаданные дистрибутивов (`pyproject.toml`, лицензии, файлы
поставки) — карточка №427.

Код пакетов сюда НЕ переезжает. Решением от 26.09 (№424) пакетная форма
одна: и плоский модуль, и модуль пакета живут под общим `src/` —

```
src/<пакет>/…/<модуль>.py     # импортируемый код: `src/<пакет>/graphs.py` → `<пакет>.graphs`
```

Прежнее гнездо `packages/<дистрибутив>/src/<пакет>/…` снято: два каталога
раскладки на один код разводили форму модуля и трижды требовали отдельной
ветки в стороже. Дистрибутив, который объявляет пакет, будет ссылаться на
`src/<пакет>/` через `packages/<дистрибутив>/`.

Имя модуля для сторожа раскладки — ИМПОРТИРУЕМОЕ (`charoite_graph.graphs`), а
не имя файла: именно его пишет автор в `import`, и именно им ключуется таблица
слоёв `docs/design/layout.json`.

Форму раскладки знает ОДНА функция в `scripts/layout_map.py` — `form()`: путь
в значение `(роль, пакет, модуль, provider)`. Роли перечислены в `ROLES`, и у
каждой есть строка в корпусе `MODULE_SHAPES` — ветка без строки корпуса
откатывается зелёной. `module_of()` и `package_of()` — её проекции. Грамматику
импорта (точечные имена, относительные `from . import …`) знает соседний
`imports_of()`.

Имена каталогов объявлены один раз — `LAYOUT_DIRS` (`src`), — и `form` читает
их оттуда. Тест-сторож собирает написания из того же объявления (голое, со
слешем, глоб) и красит прогон, если каталог назван литералом ВНУТРИ любой
функции: второй предикат пути так не написать, как бы он ни был устроен
(`startswith`, срез, сравнение сегмента, `PurePosixPath.match` с глобом).
Объявления уровня модуля — `LAYOUT_DIRS`, `ENTRY_CANDIDATES`, `_PATH`,
`TOKEN_PREFIXES` — каталоги называют намеренно: они и есть источник. Чего
сторож НЕ ловит: регулярку и склейку строк.

Ветки `form` держит корпус: тест прогоняет `MODULE_SHAPES` под трассировкой и
требует, чтобы каждая исполнимая строка `form` была пройдена. Новая форма без
строки корпуса краснеет, даже если её роль уже есть в `ROLES`.

Точка входа переживает переезд: кандидатность модуля пакета решает форма, а не
глоб `src/*.py` — иначе первый же `git mv` вынес бы её из-под охраны, а
объявить путь ручным было бы нельзя вовсе.

## Что сторож потребует

* каждый `.py` в области кода — либо модуль продукта, либо точка входа;
  файл, до которого правила не дотянулись, красит гейт, а не числится «вне
  области по политике»;
* модуль, уехавший из плоского `src/<модуль>.py` в пакет
  `src/<пакет>/<модуль>.py`, — это ПЕРЕЕЗД: гейт просит переименовать ключ в
  таблице слоёв, а не снять охрану;
* стрелки слоёв внутри пакета действуют так же, как для плоских модулей
  `src/`.

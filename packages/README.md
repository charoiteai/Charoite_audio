# `packages/` — дистрибутивы Чароита

Пока пусто: первым сюда уезжает `charoite_graph` (карточка №323, фаза 1).
Каталог заведён раньше переезда сознательно — вместе со сторожем раскладки,
который умеет его читать (№328). Иначе первый же `git mv` уезжал бы из-под
охраны: имя модуля считалось из формы `src/<имя>.py`, и всё, что не подходило
под неё, переставало быть модулем — без рёбер импорта, без слоя, без красного.

## Форма

```
packages/<дистрибутив>/
  pyproject.toml          # свой, со своими зависимостями
  src/<пакет>/…           # импортируемый код: `packages/p/src/p/x.py` → `p.x`
  tests/…                 # тесты пакета
```

Имя модуля для сторожа раскладки — ИМПОРТИРУЕМОЕ (`charoite_graph.graphs`), а
не имя файла: именно его пишет автор в `import`, и именно им ключуется таблица
слоёв `docs/design/layout.json`.

Форму раскладки знает ОДНА функция в `scripts/layout_map.py` — `form()`: путь
в значение `(роль, дистрибутив, пакет, модуль)`. Роли перечислены в `ROLES`,
и у каждой есть строка в корпусе `MODULE_SHAPES` — ветка без строки корпуса
откатывается зелёной. `module_of()` и `package_of()` — её проекции, тесты
пакета `decide()` спрашивает у неё же. Грамматику импорта (точечные имена,
относительные `from . import …`) знает соседний `imports_of()`.

Владелец объявлен в самом модуле (`SHAPE_OWNER`), и тест-сторож читает это
объявление: любое упоминание каталога раскладки (`src`, `packages`, `tests`)
вне владельца красит прогон — неважно, как написан второй предикат
(`startswith`, срез, `PurePosixPath.match` или сравнение сегмента).

## Что сторож потребует

* каждый `.py` в области кода — либо модуль продукта, либо точка входа;
  файл, до которого правила не дотянулись, красит гейт, а не числится «вне
  области по политике»;
* модуль, уехавший из `src/` в пакет, — это ПЕРЕЕЗД: гейт просит переименовать
  ключ в таблице слоёв, а не снять охрану;
* стрелки слоёв внутри пакета действуют так же, как в `src/`.

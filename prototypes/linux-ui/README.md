# Лаборатория интерфейса Чароита для Linux

Отдельный интерактивный веб-прототип, а не порт SwiftUI и не рабочий аудиопродукт.
Основной код приложения не изменён. Все три встречи, участники, решения и
стенограммы вымышлены; модели, микрофон, облако и файлы пользователя не используются.
Изменения названий, отметок задач и плотности хранятся только в памяти вкладки.

## Запуск

Из корня репозитория (Python 3, браузер; runtime-зависимостей npm нет):

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory prototypes/linux-ui
```

Открыть `http://127.0.0.1:8765`. Сервер привязан только к loopback.
Остановить Ctrl+C. Это локальный адрес среды, не публичная ссылка предпросмотра.

## Что можно попробовать

- Сегодня, архив, задачи, память и настройки.
- Поиск по содержимому и участникам, пустую выдачу и сброс.
- Карточку встречи: резюме, минутки, разбор, стенограмму; переименование
  с проверкой пустого названия, отменой и сохранением.
- Задачи с общим состоянием между карточкой и списком задач.
- Связи «тема → решение → участники → встреча-источник».
- Демонстрационный сбой обработки: стенограмма доступна, повторный запуск
  честно объясняет отсутствие модели.
- Узкий экран: список и карточка отдельно, возврат сохраняет поиск.
- Tab/Shift+Tab, ссылку пропуска навигации, Enter и Escape в диалогах.

Палитра и геометрия следуют `docs/DESIGN.md`; структура взята из
`MeetingLibraryView`, `MeetingCardView`, `SettingsView`. SwiftUI-компоненты
не исполняются в браузере. Память представлена карточками связей, не графовым
движком. Загрузки/импорта файлов и асинхронной обработки здесь нет.

## Проверка в Chromium

Сервер должен быть запущен отдельно. Зависимости теста изолированы здесь:

```sh
cd prototypes/linux-ui
npm install
CHROMIUM_PATH=/usr/bin/chromium npm test
```

`EVIDENCE_DIR` задаёт каталог скриншотов (по умолчанию
`/tmp/charoite-prototype-evidence`). Playwright использует установленный Chromium;
другой путь задаётся через `CHROMIUM_PATH`. В облачной среде Playwright 1.62.1
уже установлен. Тест проверяет реальные клики/ввод, ошибки JS, отсутствие
внешних запросов, переходы, диалоги, валидацию, задачи и ширину 390/320 px.
Проверки доступности базовые; проверка экранным диктором не проводилась.

При прогоне найден и исправлен сброс компактной плотности после поиска:
добавленный тест сначала падал (`18px != 10px`), после исправления проходит.
По скриншотам навигация на узком экране заменена с обрезанной горизонтальной
ленты на перенос строк. Исправлены возврат фокуса после переименования
и скрытие ссылки пропуска навигации вне фокуса.

Следующий шаг для основного приложения: согласовать взаимодействия и проверить
их в настоящем SwiftUI на Mac, прежде чем переносить изменения. Этот прототип
не доказывает наличие или исправление дефектов macOS-приложения.

### Уточнение UX после эвристического аудита

- При нулевой выдаче справа больше нет прежней встречи. Если совпадения есть,
  но выбранная встреча в них не входит, предлагается выбрать результат.
- На 390 px первая карточка начинается примерно на 324 px вместо 506 px.
  Предупреждение «Вымышленные данные · без записи и моделей» остаётся видимым.
- Очистка появляется только при введённом запросе. Переименование — вторичное
  действие под названием; объяснение недоступной записи — ссылка «Почему?».
- Связанная тема доступна до содержимого встречи. Источники в памяти названы
  заголовком и датой встречи.
- Контраст основной кнопки увеличен с 4,47:1 до 5,55:1.

Эти условия проверяются браузерными утверждениями, включая отсутствие старой
карточки при поиске, положение элементов, размеры целей и вычисленный контраст.

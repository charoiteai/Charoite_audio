# Privacy

*[**English**] · [Русский](docs/ru/PRIVACY.md) · [中文](docs/zh/PRIVACY.md)*

Charoite is built local-first. Concretely:

- **No telemetry.** Zero analytics, crash reporters or "anonymous usage stats". Grep the code.
- **No network calls** except to services you run yourself on localhost (Ollama at `127.0.0.1:11434`, optional local STT stream server) — unless you explicitly enable the cloud layer. Two exceptions are not the cloud layer and are named here rather than hidden: a **daily version check** to `api.github.com` (on by default, `check_updates: false` turns it off; nothing about you is sent, but the request itself reveals your IP and that you run Charoite), and the **one-time model download** on first use, from Hugging Face or the mirror in `scripts/get_models.py`. Both obey the kill switch: with `CHAROITE_NO_CLOUD=1` the version check is skipped and model downloads are refused outright instead of quietly reaching the network mid-meeting. The LLM address is guarded by code, not convention: every reader gets it from `src/privacy.py`, and a non-loopback `llm.base_url` (another machine, a cloud endpoint) refuses to start unless you set an explicit `llm.allow_remote: true` — transcripts follow that URL, so pointing it elsewhere is a privacy decision, not a tuning knob.
- **The same rule applies inside the app.** The "Ollama" field in Settings used to accept any address and send requests to it, bypassing `privacy.py` — one layer kept the promise while the other did not, even though semantic index chunks (the whole meeting archive) and the live transcript travel this path. Since 0.48.0 the app decides exactly as the daemon does: loopback always passes, anything else only with an explicit `llm.allow_remote: true`, and never under the kill switch. A rejected address is not silently swapped: Settings shows a warning with the address and the reason, and requests go to `localhost`.
- **Cloud layer is opt-in and off by default.** There are exactly four switches, all of them `false` in the shipped config, and this list is the whole truth — a test fails if a fifth one appears and is not documented here:
  - `cloud_enrich` — after you stop the meeting, the **full transcript** goes to Claude for a debrief. The same key also authorizes the **nightly graph reviews**: the cores revision (up to 60k characters of Cores) and the dossier review send graph-derived text to Anthropic overnight.
  - `cloud_live` — mid-meeting questions go out as **chunks of the transcript**, one request per question.
  - `cloud_hints` — cloud refinement of live hints: the transcript is sent on **every hint**, i.e. a steady stream for as long as the meeting runs, not a single package. Requires `cloud_live` as well.
  - `cloud_edit_graph` — the only switch that grants **writing, not sending**: the post-meeting debrief may rewrite graph files itself instead of just filing a report (the nightly dossier review stays text-only: the model returns text, Charoite writes the file). Requires `cloud_enrich` as well. Without it the cloud gets read-only tools (`Read`, `Grep`, `Glob`) and returns the review as text — Charoite writes the file. What goes to the cloud is assembled by Charoite: this meeting's files as text inside the request (the log states how many files and characters were sent). In both graph-backed modes the working directory is the graph, not the repository — past meetings in `transcripts/`, recordings, logs, `.git` and `config/config.yaml` are out of reach; the text-only fallback (no graph) runs without any file tools at all. Transcripts, minutes, the meeting archive folders and `## Author edits` are never touched, and every edit is backed up first. This is enforced by code, not by the wording of the request: the worker snapshots the whole graph (every file, not just Markdown) before the run, compares afterwards and reverts anything that was off-limits — edited, deleted or newly created in a protected place (transcript copies, archive folders, hidden snapshot folders, the author section). Files outside the graph are guarded one layer earlier, by the CLI's own permission rules: the debrief sees explicit tools only (`Read`, `Grep`, `Glob`, plus `Edit`/`Write` with the switch), `Read(/**)` and the optional `Edit(/**)` are anchored to `cwd=graph`, `dontAsk` rejects every path outside that graph instead of prompting, and shell, network and MCP tools are absent. If the graph is missing, is `/`, or is the home directory, the call becomes text-only rather than falling back to file access in `transcripts/`. The run has a timeout and an answer check: a truncated review is never published as a finished one — it is kept alongside with a `.partial` suffix.

  When enabled, they run the `claude` CLI under your own subscription; what you choose to send goes to Anthropic under your account and their terms. Turn them off and Charoite is fully offline.
- **One place decides, and the check sits where the request leaves.** Every "may this leave the machine?" question is answered by `src/privacy.py`. The check lives at the network exit itself, not only at the caller: a manual request (the ☁️ button, ⌘⇧⏎) used to reach the API past a switch that was only consulted on the automatic path. Silence in the config means *no* — a missing key, `"false"`, `0` or an empty value are never read as permission. `tests/test_privacy_defaults.py` and `tests/test_cloud_call_sites.py` hold both properties, so this bullet is a test rather than a promise.
- **Kill switch.** `CHAROITE_NO_CLOUD=1` (or the historical `SUFLER_NO_CLOUD=1`) in the environment forces the cloud layer off whatever the config says — "run this one strictly offline" should be an env var, not a YAML edit before someone else's meeting. It also overrides `llm.allow_remote`: with the switch set, a non-local `llm.base_url` is refused too, so "nothing leaves this machine" means exactly that.
- **Only your account can read the meeting.** Recordings, transcripts, minutes, the search index and daemon logs are created for the owner alone — files `0600`, directories `0700`. Until 0.50 they were written with the default mask (`0644`/`0755`), so any second account on the same Mac could read every meeting without asking for anything. Existing installations are migrated on the next daemon start, and `tests/test_private_permissions.py` fails if a new entry point forgets the mask. What this does not cover: copies you sync elsewhere (iCloud, Time Machine) follow that service's rules, and an admin of the machine can always read your files.
- **Recordings are temporary.** Full-meeting audio is kept only to rebuild an accurate transcript after the meeting and is deleted after `record_keep_days` (default 2). Cleanup runs when the daemon starts, not only when a new meeting begins — so recordings expire on schedule even if you do not record for a week or turn `record` off.
- **A meeting can be forgotten entirely.** `record_keep_days` covers the audio; `scripts/forget_meeting.py <date|stamp>` covers the rest: the transcript and its derivatives, the meeting folder in the archive, the meeting node, the transcript copy under Documentation, chronicle lines in Cores (together with the fact that came from that meeting), links in Dossiers and people's nodes, the pipeline status under `logs/meeting-status/` and the meeting's graph/cloud-review logs, every `<stamp>_*.md` artefact copied under Documentation (not just the bare transcript), and the meeting's files inside `.cloud_backup/` — the pre-edit snapshots taken before a cloud graph review copy the graph wholesale, and forgetting has to reach those copies too. By default it only prints the plan — deletion is irreversible and needs `--yes`; edits to surviving nodes are backed up into `.forget_backup/`. What it cannot do: reach copies already synced to iCloud or Time Machine, or clean up files held by other participants.
- **Audio imported into the graph is yours to manage.** `scripts/import_meeting.py` copies the source file into the meeting folder so the transcript can be rebuilt later. That copy lives in your graph (often iCloud) and is *not* covered by `record_keep_days` — delete the meeting folder if you want it gone.
- **Models are downloaded once.** On first run the selected STT model is fetched from Hugging Face; the diarization model is installed on demand by `scripts/get_models.py --diar`, which prints the URL before connecting. Everything after that is local: neither the daemon nor the app ever fetches models. If you need a machine that never reaches the network, pre-populate `models/` and run offline.
- **No voice biometrics stored.** Live diarization keeps speaker embeddings in RAM for the duration of the meeting only. Nothing voice-derived is written to disk.
- **Your data is plain files.** Transcripts, summaries and the knowledge graph are Markdown in folders you choose. Delete them, sync them, encrypt them — they are yours.

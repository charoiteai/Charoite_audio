# Charoite 安卓端 — 伴侣应用

*[English](README.md) · [Русский](README.ru.md) · [**中文**]*

平板（或手机）是桌上的麦克风，大脑仍留在 Mac 上。这是一个 Compose
伴侣应用（Android 8+）：录制会议、语音笔记和日记，并回读知识图谱；
而所有重活（语音识别、说话人分离、大模型、图谱构建）都在你的 Mac 上完成。

## 功能

- **录音** — 三种类型：会议 / 笔记 / 日记。通过前台服务实现后台录音
  （从界面启动后可切换到其他应用），实时电平指示，通知栏与锁屏上的
  计时器，通知中直接带「停止」按钮。
- **投递** — 录音保存到你通过系统选择器（SAF）一次性选定的文件夹。
  Mac 需要看到同一个文件夹：通过 Syncthing 或任意同步工具；在 Mac 上
  它就是导入文件夹。暂时没有同步？设备内的队列会在每次启动和每次
  停止后重发。录音期间重新打开应用不会触碰正在写入的文件；崩溃恢复
  会先验证文件再移入队列，提供方复制失败也不会留下只写了一半的 WAV。
  语音笔记（`note_`/`diary_` 前缀）会自动进入 Mac 的笔记流程。
- **会议列表** — 读取所选图谱中「Встречи」文件夹下的 `.md` 文件，
  最新在前，点击查看全文。
- **任务** — 图谱中所有 `- [ ]` 复选框汇总为一个列表；勾选直接写回
  markdown 文件，因此 Mac、Obsidian 和平板始终一致。

## 录音格式

16 kHz、单声道、16 位 WAV — 正是 Mac 端识别所需的格式，全程无需转码
（每小时约 115 MB）。

选择 WAV 不是因为体积，而是因为中断：MPEG-4 容器若没有正常的
`stop()` 就缺少 `moov` 原子，任何软件都读不出来，而别人的一小时会议
无法重录。录音过程中会持续刷新 WAV 头，因此即使被系统杀死，文件仍然
有效；应用会在下次启动时把实际长度写入其中。

## 构建与安装

需要 JDK 17 和 Android SDK（compileSdk 35）。SDK 路径写在
`app-android/local.properties`（`sdk.dir=...`），该文件不在仓库中。

```bash
cd app-android
./gradlew testDebugUnitTest        # 图谱解析与 WAV 头
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

真机检查（麦克风、服务、文件完整性）：

```bash
./gradlew connectedDebugAndroidTest
```

## 首次设置

1. **设置** → 「投递文件夹」→ 选择你与 Mac 同步的文件夹
   （在 Mac 上就是 Charoite 的导入文件夹）。
2. **设置** → 「图谱根目录」→ 指向 Obsidian 图谱文件夹，
   即包含「Встречи」目录的那一个。

两项都只需选择一次：文件夹授权在重启后依然有效。

## 隐私

本应用完全没有网络权限 — 可在 `AndroidManifest.xml` 中核对。音频只能
通过你选择的文件夹离开设备。没有账号、没有遥测、没有第三方服务。

## 尚未实现

通过 Wi-Fi 直接投递到 Mac：它需要一个 iPhone 与 Android 共用的协议
（mDNS + 配对码 + TLS），详见 ROADMAP。在此之前由 Syncthing 或任意
同步工具负责文件夹同步，应用并不关心具体是哪一个。

安卓端录音带有 `android_` 前缀，因此在导入文件夹中一眼就能看出会议
是用什么设备录制的。

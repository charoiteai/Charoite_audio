# №955 — независимое входное ревью Terra

Снимок: MANIFEST SHA-256 `07604bc6d8c74f94c5a48beee3181d3d21f2b889c796dc3a7dc0f01b1d3c1226`; база `2106ed52c9b3f70f5d0c8b6363e9e3171ae767be`. Проверка постановки и переданного исходного текста; эксперименты и приватный wrapper не выполнялись и не читались.

## Critical

1. `docs/diagnostics/nightly-955/INPUT.md:13-16,29-30`: наследуемый при `exec` дескриптор не гарантирует его сохранение произвольными потомками. Например, команда запускает долгий процесс через Python `subprocess` с обычным `close_fds=True`, затем погибает: потомок продолжает работу без дескриптора, ядро снимает flock и второй wrapper может начать параллельно. Минимум — ограничить контракт только процессами, реально сохраняющими этот FD, и доказать сохранение на всех существенных границах реальной цепочки, включая UX и фоновые дочерние процессы; если обязательна защита произвольных потомков после смерти родителя, выбрать обеспечивающий это механизм и отдельно доказать сценарий. Один специально наследующий FD синтетический потомок недостаточен.

## Important

1. `docs/diagnostics/nightly-955/INPUT.md:29-32`: тест требует убить владельца, но одновременно запрещает process signals. Без согласованного безопасного способа завершить именно синтетического владельца сценарий нельзя выполнить по плану. Уточнить разрешённый механизм для созданных тестом изолированных процессов с проверкой PID/очисткой или явно оставить сценарий непроверенным; не сигнализировать реальным процессам.
2. `docs/diagnostics/nightly-955/INPUT.md:11-16`: постоянство имени файла не гарантирует общий inode, если кто-то заменит или удалит файл либо родительский каталог; два корректно открытых дескриптора тогда получат независимые flock. Зафиксировать доверенный неизменяемый каталог и запрет внешней замены как предусловие; проверить после открытия тип файла через `fstat`, не следовать конечной символьной ссылке атомарно и документировать оставшуюся границу. При отсутствии этого предусловия не заявлять безусловную взаимную исключительность.
3. `docs/diagnostics/nightly-955/INPUT.md:26-30`: требуется явно закрепить сценарий `state=failed` при `rc=0`: `scripts/nightly.sh` допускает такой исход для необязательного шага, поэтому фикстура, считающая успешность только по коду процесса, может ложно подтвердить исправление. Проверить повторный запуск при этом сочетании и отдельный пропуск тяжёлой работы при `state=ok`.

## Minor

1. `docs/diagnostics/nightly-955/INPUT.md:18-23`: уточнить, что hash-bound относится к проверке ожидаемого исходного хеша до точечной трансформации и фиксации хешей результата и argv; любое расхождение должно завершать staging ошибкой. Проверка установленной цепочки остаётся отдельной незавершённой приёмкой, а не следует из staging.

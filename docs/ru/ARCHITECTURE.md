# Архитектура

*[English](../ARCHITECTURE.md) · **Русский** · [中文](../zh/ARCHITECTURE.md)*

## Общая схема

```
микрофон ──────┐                        ┌─ живая стенограмма (абзацы по голосам)
               ├─ AudioHub ─ STT ─ демон ┼─ циклы: ⚡ ответы · тезисы · минутки
системный звук ┘  (чанки 3 с)           │   · имена · разметка диалога · контекст
(ScreenCaptureKit; BlackHole — запасной) └─ NDJSON stdout ←→ stdin команды (UI)

Стоп → пересборка записи → обновление графа → архив + Сводка → [опциональный разбор в облаке]
```

По умолчанию всё работает локально на вашей машине; вызовы LLM и эмбеддингов идут только на loopback (Ollama / MLX). Облачный слой выключен по умолчанию (см. [PRIVACY.md](PRIVACY.md)). Единственный собственный сетевой запрос приложения вне встреч — опциональная проверка релизов на GitHub.

## Демон (`src/daemon.py`)

Один процесс крутит потоки вокруг общего защищённого замком `Transcript` (`src/transcript.py`; рантайм-модули не импортируют `src/main.py`): цикл STT, быстрый триггер вопросов, мгновенные ответы, автоподсказки, со-мышление (тезисы), нить встречи, живые минутки, распознавание имён, разметка диалога, живой контекст из архива, автостоп, опциональный облачный цикл и heartbeat.

- **Протокол:** события NDJSON идут в stdout (`transcript`, `thesis`, `hint`, `status`, …); команды приходят в stdin (`hint`, `ask <вопрос>`, `expand [тема]`, `cloud`, `summary`, `set hints|theses|cloud on|off [quiet]`, `stop`). Второй экземпляр блокируется через `flock` (`logs/daemon.lock`).
- **Ошибки отдельно от контента:** статусы демона несут флаг `"error": true` при сбое; ошибка модели никогда не затирает последнюю удачную подсказку на экране.
- **Экспериментальная хронологическая лента (opt-in):** при `sufler.live_feed: true` работают `grounded_feed.semantic.SemanticActor` и `grounded_feed.local_runner.LocalFeedRunner` строго под `LocalLoopbackAuthority` (ноль облачного трафика). Принятая речь, утверждения, открытые вопросы и курсор живут в одном неизменяемом состоянии, а на Стопе сохраняется `<transcript>.grounded.json`. См. [live-feed.md](../live-feed.md).

### Захват звука и единая ось времени

Приложение macOS захватывает системный звук (а с macOS 15 и микрофон) через ScreenCaptureKit в растущий потоковый файл по манифесту `data/sck_stream.json`. `AudioHub` читает его как `tail -f`. Без свежего манифеста срабатывает запасной путь: BlackHole + микрофон через PortAudio.

`ChannelAxis.swift` раскладывает каждый буфер по его `synchronizationClock` (переведённому в host time через `CMSyncConvertTime`). Короткие пропуски (0.1–2 с) заполняются тишиной (до 30 с при позднем старте канала — половина `AudioHub.BUF_CAP_S`); более длинные разрывы или откат метки перепривязывают ось без потери звука. Два канала разделены, что сразу даёт разделение «я / собеседник»; при одновременной речи чанк микрофона отбрасывается как эхо колонок.

### Метки каналов и владелец (`src/channel_labels.py`)

`ChannelLabels` — единый источник истины из конфига:
- `mic_raw` — сырая метка канала (`sufler.user_name` либо «Я», если нет коллизии с нейтральной меткой),
- `mic_signed` — подпись владельца для стенограмм и атрибуции в графе,
- имя владельца для текстового сопоставления.

### Приоритет живой встречи и расписание (`src/live_gate.py`, `src/machine_power.py`)

Живая встреча всегда приоритетнее фона (пересборка записей, извлечение графа, ночные досье, ревизия ядер):
- **Замок встречи:** `logs/daemon.lock` держится всё время записи (консольный `src/main.py` также берёт `logs/console.lock`). Фоновые процессы проверяют его неблокирующим `flock` и ждут между чанками.
- **Очередь пересборок:** `logs/rebuild.lock` гарантирует не более одной пересборки стенограммы одновременно на машине.
- **Поиск демона:** `live_gate.daemon_process` находит живой демон по точному шаблону `python` + скрипт, независимо от корня данных.
- **Устойчивость транспорта (`src/llm.py`):** `llm.stream` и `llm.complete` повторяют временные `503`/`429`/`502` с backoff, считают `{"error": ...}` внутри потока ошибкой и ведут учёт активных генераций, чтобы watchdog отличал долгий расчёт от зависания.
- **Внутри демона:** мгновенная подсказка приоритетнее фоновой нити встречи; нить работает строго на лёгкой модели и сразу уступает слот подсказке.
- **Питание:** `src/machine_power.py` отслеживает режим энергосбережения macOS, чтобы честно сообщать о замедлении подсказок.

### Решающий гейт в тени (`src/decision_gate.py`)

Опциональный (`sufler.decision_gate_shadow: true`) исследовательский гейт рядом с мгновенными ответами (`⚡`). Пишет в лог только числа и метаданные вердикта (без текста разговора); оценивается через `scripts/gate_bench.py`. См. [research/decision-gate.md](../research/decision-gate.md).

### Опциональный облачный слой (`src/cloud.py`, `src/privacy.py`)

Все пять разрешений (`cloud_enrich`, `cloud_live`, `cloud_hints`, `cloud_edit_graph`, `cloud_engine`) описаны в `src/privacy.py` и выключены по умолчанию:
- **CLI-циклы (`cloud_enrich`, `cloud_live`, `cloud_hints`, `cloud_edit_graph`):** вызывают `claude -p` по подписке (без API-ключей в окружении), проверяют код выхода и непустой stdout и не глотают отсутствие бинарника.
- **Песочница графа:** облачный разбор досье/графа никогда не правит рабочую папку Obsidian напрямую. Он работает по копии (`src/file_locks.py`), проверяет дифф против симлинков и разрушительных правок и применяет принятое атомарно под общим замком графа.
- **Облачный чат (`llm.engine: cloud` + `sufler.cloud_engine: true`):** направляет чат-запросы на OpenAI-совместимый шлюз с ключом в отдельном файле `0600` (`llm.cloud_key_file`, никогда в `config.yaml`). Секреты вырезаются из ошибок; STT, диаризация, эмбеддинги и NLI всегда остаются локальными.

## Диаризация: два прохода

1. **Живой проход (`src/diarize_live.py`):** поканальное отслеживание голосов (ONNX ERes2Net + pyannote) и опциональный потоковый Nemotron (`src/live_nemotron.py`). При отставании STT уступает ему ресурсы.
2. **Поствстречный проход (`src/rebuild_transcript.py`, `src/diarize.py`, `src/diarize_nemotron.py`):** размечает полные записи после Стопа, фильтрует эхо, выделяет владельца, склеивает осколки и сопоставляет прозвучавшие имена с вето по регистру голоса.

Подробная спецификация, контракты и пороги: [DIARIZATION.md](DIARIZATION.md).

## Поствстречный конвейер (`src/graph_updater.py`)

После Стопа запускается цепочка: пересборка записи → генерация минуток/разбора/тезисов → экспорт в архив (`src/meeting_archive.py`) → обновление графа знаний → опциональный облачный разбор.

- **Паспорта производных (`src/transcript_origin.py`):** минутки, разбор, тезисы и нормализованные поручения хранят хеш и происхождение исходной стенограммы. После пересборки с диаризацией нетронутые автодокументы пересобираются начисто (прошлая версия уходит в `transcripts/.prev/`), а правленные вручную сохраняются и получают только обновлённые имена спикеров.
- **Идемпотентность (`src/once.py`):** шаги защищены от повторного выполнения при ретраях и восстановлении после сбоя.
- **Нормализация поручений:** поручения из минуток детерминированно приводятся к стандартным чекбоксам `- [ ]`, чтобы попадать в окно Задач.

## Граф знаний (`src/charoite_graph/`)

Граф знаний — обычная папка Obsidian с markdown-файлами: файлы на диске являются единственным источником истины (без внешних БД).

- **Структура (`src/charoite_schema.py`, `src/graph_links.py`):** Встречи (`Встречи/`), Люди (`Люди/`), Системы (`Системы/`), Ядра (`Ядра/`), Блокеры (`Блокеры/`) и Досье (`Досье/`). Разные сферы жизни могут храниться в отдельных папках-графах.
- **Frontmatter и редиректы:** `src/charoite_graph/frontmatter.py` управляет YAML-шапкой; `src/charoite_graph/redirects.py` перенаправляет ссылки слитых узлов на канон.
- **Атомарная запись (`src/charoite_graph/safe_write.py`):** каждое обновление узла пишется во временный файл и подменяется атомарно под общим замком (`src/file_locks.py`), чтобы узел не оборвался на середине записи.
- **Гигиена графа:** нейтральные метки (`Собеседник 3`) и разовые фоновые упоминания не создают узлов людей; аудит и чистку выполняют `scripts/graph_doctor.py`, `scripts/dedup_graph.py` и `scripts/migrate_placeholders.py`.

### Досье: слой сводок между поиском и графом

Ночью (`scripts/nightly.sh` под контролем `scripts/night_gate.py`) локальная модель собирает и инкрементально обновляет досье на каждое сквозное Ядро (окрестность 1-hop): текущее состояние, хронология, решения, открытые вопросы и участники со ссылками на источники.

- **Инкрементальные отпечатки:** каждое досье хранит хеш источников; неизменённые темы не будят модель.
- **Сохранение ручных правок:** раздел «Правки автора» переживает автоматические пересборки.
- **Приоритет поиска:** поиск сначала смотрит в лексический индекс досье (`Досье/_index.json`), но чётко разделяет первичные заметки встреч и производные сводки.

## Модель памяти и поиск (`src/brain.py`, `src/charoite_graph/graph_search.py`)

- **Единый шлюз LLM (`src/llm.py`):** вызовы чата и извлечения работают с закреплённой `temperature: 0` для воспроизводимости.
- **Единый эмбеддер (`bge-m3` через Ollama):** семантический поиск и ревизия ядер (Tier-3).
- **Локальный судья NLI (`src/nli.py`, ONNX):** смысловой дедуп тезисов, проверка эквивалентности ядер и zero-shot-запас решающего гейта. См. [MODELS.md](MODELS.md).
- **Профили поиска (`src/brain.py`):** `brain.search(profile, query)` настраивает выборку для вопросов к архиву, живого контекста встречи (`src/threads.py`) и предподготовки. Файлы режутся на чанки по заголовкам; смежность индексируется по относительному пути; скрытые файлы iCloud (`UF_HIDDEN`) обрабатываются явно; бюджет контекста ограничивает долю одного источника 40 %.
- **Честная граница ответа:** ответ никогда не утверждает, что проверил непрочитанные файлы; индексные `_MOC.md` служат навигацией, а не источником фактов.
- **MCP-сервер (`src/mcp_server.py`):** отдаёт статус, стенограмму, подсказки, минутки и обновление графа MCP-клиентам строго в пределах `CHAROITE_ROOT`.
- **Измерение качества:** `scripts/memory_bench.py` проверяет поиск и ответы на демо- или пользовательских вопросах; `scripts/retrieval_compare.py` сравнивает ранжирование офлайн на замороженных оценках.

## Устойчивость к сбоям и целостность данных

- **Один штамп на сессию:** сырой PCM и стенограмма носят один штамп. При штатном Стопе PCM конвертируется в WAV; после падения при следующем старте незавершённые `.pcm` подбираются автоматически.
- **Инварианты звука:** `AudioHub` гарантирует строгий учёт сэмплов и честную деградацию каналов (монотонный возраст мёртвого канала, видимость за 30 с). См. [INVARIANTS.md](INVARIANTS.md).
- **Остановка записи:** Стоп дочитывает буфер, сохраняет финальную стенограмму и нить без очистки экрана и передаёт запись на фоновую пересборку.
- **Типы дублей:** смысловые дубли ядер (ревизия Tier-3 + `scripts/dedup_graph.py`), намеренные зеркала архива вне графа и конфликтные копии iCloud (`Минутки 2.md`).
- **Гарантии ночи (`scripts/nightly.sh`):** четыре слота `launchd` переживают закрытый ноутбук; потолок `CHAROITE_NIGHTLY_UNTIL` не даёт ночи заехать на рабочий день; живая встреча вытесняет тяжёлые ночные шаги; ручные правки ядра не затираются.
- **Эффективность UI:** тикающие значения (таймер записи) изолированы в отдельных view, а publish-гейты сравнивают видимое состояние, исключая лишние перерисовки SwiftUI.

## Границы слоёв (`docs/design/layout.json`)

Раскладка кода проверяется механически через `scripts/layout_map.py` и `tests/test_import_boundaries.py` (в `scripts/preflight.sh` и CI):
- `docs/design/layout.json` — единственный машиночитаемый источник истины: принадлежность модулей слоям, разрешённые направления импортов, allowlist долга, ручные точки входа, `run_contracts` и двери `mutation_critical`.
- `docs/design/layout.md` генерируется из `layout.json` и проверяется на свежесть.
- Каждый путь к исполняемому файлу в коде или документации (`src/*.py`, `scripts/*`, `app/*.sh`) проверяется на существование на диске.

## Проверка готовности и обновления приложения

- **Диагностика (`scripts/doctor.py`):** проверяет Python-рантайм, конфиг, зависимости, аудиоустройства, Ollama/модели, NLI и папку графа без доверия старому состоянию папки данных.
- **Обновления релизов:** macOS-приложение периодически проверяет публичный API релизов GitHub (отключается `sufler.check_updates: false` или `CHAROITE_NO_CLOUD=1`). Перед подменой бандла проверяются подписанный ed25519-ключом мейнтейнера манифест (версия + sha256), подпись Apple Developer ID и отсутствие активной записи. См. [RELEASING.md](RELEASING.md).

## Разделение кода и данных

Код и рабочие данные строго разделены, чтобы подписанный `.app`-бандл оставался read-only:

- **Корень кода:** `src/`, `scripts/`, `config/config.example*.yaml`, `pyproject.toml`, `requirements-nemotron.lock`. Собирается в `Charoite.app/Contents/Resources/charoite` через `app/stage_code.sh` (вызывается из `app/make_app.sh`).
- **Корень данных:** `config/config.yaml`, `recordings/`, `transcripts/`, `logs/`, `models/`, `engines/`, `backups/`. Управляется `src/charoite_paths.py`: точки входа явно задают корень через `CHAROITE_ROOT` / `use_data_root()` и отказываются запускаться без него (код `5`, `EXIT_ROOT_UNNAMED`; код `11`, `EXIT_PRIVACY_REFUSED` при запрещённом удалённом URL модели). Корень данных внутри `.app` запрещён.
- **Никаких снимков корня при импорте:** модули вызывают `resolve_root()` в момент работы, не кешируя `ROOT` на уровне модуля (контролируется `scripts/layout_map.py`).
- **Дочитывание отказа при старте:** приложение (`DaemonLaunch.swift`) дочитывает stdout демона до EOF (с ограниченным потолком для дочерних процессов), прежде чем объявлять завершение, чтобы статус причины отказа никогда не терялся.

### Идентичность графа и совместимые замки бэкапов

Запись в граф идентифицирует каталог через открытый файловый дескриптор (физический путь на macOS, путь дескриптора на Linux) без свёртки регистра и Unicode. `GraphAddresses` один раз за мутацию фиксирует физический вид графа и пути бэкапов, песочницы, карантина и очистки (`mutation_snapshot` / `mutation_lock`), отказывая в записи при сбое идентификации. CLI-писатели с общим замком берут упорядоченную группу основного и подтверждённых старых замков с общим дедлайном и отпускают всю группу при частичном отказе.

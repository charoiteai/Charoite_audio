# Политика безопасности

*[English](../../SECURITY.md) · **Русский** · [中文](../zh/SECURITY.md)*

Charoite работает целиком на машине пользователя, поэтому большая часть
классической веб-поверхности атак к нему неприменима — но баги в
обработке аудио, файловых путях или локальных HTTP-вызовах всё равно
значимы для безопасности.

**Сообщайте об уязвимостях приватно** через GitHub: Security → Report a
vulnerability (приватный advisory) или письмом на charoiteai@gmail.com.
Не заводите публичные иссью по проблемам безопасности.

Ответа можно ждать в течение нескольких дней. Поддерживаемая версия:
`main`.

## Модель угроз в один абзац

Актив — собственные встречи пользователя: записи, стенограммы и
построенный по ним граф знаний. Серверной части нет. Поверхность атаки,
которая остаётся: данные, **покидающие** машину (опциональный облачный
слой); чужие слова, **входящие** в модели (prompt injection из
стенограмм); канал **обновлений и зависимостей**; и баги, способные
локально угробить запись. У каждой — своя защита ниже.

## Что покидает машину

- **По умолчанию — ничего.** STT, диаризация, LLM и эмбеддинги работают
  на localhost; `src/privacy.py` — единственная инстанция для каждого
  сетевого выхода, и согласием считает только явное `true` в конфиге.
- **Облачный слой включается по-способностям** — у живых ответов,
  уточнения подсказок, пост-встречной ревизии и правки графа свои ключи;
  правка графа вдобавок сначала бэкапит файлы и держит границы того, что
  модели можно трогать. `CHAROITE_NO_CLOUD=1` — рубильник, перекрывающий
  любой конфиг на каждом пути.
- CLI подписки запускается с вычищенным из окружения `ANTHROPIC_API_KEY`.
  Точная таблица ключей и гарантии: [PRIVACY.ru.md](PRIVACY.md).

## Prompt injection

Стенограммы встреч, ядра и досье — чужие слова, поэтому каждый headless
`claude -p`, который запускает приложение, изолирован. Вызовы «только
текст» несут полный запретительный список инструментов плюс
`--setting-sources ""` и `--strict-mcp-config` (`cloud.text_only_args()`):
инъецированные инструкции не могут читать файлы, выполнять команды или
ходить в сеть — даже когда собственный `~/.claude/settings.json` хозяина
машины эти инструменты разрешает. Единственный вызов, законно трогающий
файлы (пост-встречная облачная ревизия), получает права от явного
privacy-ключа и ту же изоляцию настроек. `tests/test_cloud_isolation.py`
сканирует исходники и валится на любом новом неизолированном вызове.

## Запись — fail-closed

Идущая запись — самый ценный локальный актив, поэтому операции вокруг неё
отказывают в безопасную сторону: встроенный апдейтер перепроверяет живую
запись непосредственно перед подменой бандла, а его helper отказывается
трогать установку, пока процесс приложения жив; файлы записи открываются
эксклюзивно (`"xb"`), и коллизия имён — видимая ошибка, а не тихая
перезапись; на остановке звук передаётся атомарными переименованиями.
Механика: [ARCHITECTURE.md](ARCHITECTURE.md), «Как встреча переживает падение».

## Supply chain и целостность релизов

- Все workflow работают с минимальными `permissions:` и
  `persist-credentials: false`; пользовательский ввод попадает в скрипты
  через переменные окружения, а не интерполяцией. В CI zizmor гейтит
  безопасность workflow, dependency review — уязвимости высокой
  серьёзности, CodeQL идёт на каждый push.
- Actions пришпилены к версионным тегам по задокументированной политике
  (`.github/zizmor.yml`); dependabot еженедельно обновляет actions,
  swift, gradle и pip.
- Релизы собираются строго с тега релиза. Встроенный CPython пришпилен по
  версии и сверяется по sha256 с опубликованным upstream `SHA256SUMS`;
  `Charoite.app.zip` и `Charoite.dmg` уходят с опубликованными sha256, и
  встроенный апдейтер сверяет контрольную сумму до установки.
- **Известное ограничение:** сборки пока подписаны ad-hoc (первая
  установка — правый клик → Открыть; задокументировано в README).
  Developer ID и нотаризация — в планах; блокер — entitlements
  hardened runtime для доступа встроенного python-демона к микрофону.

## Обезличивание этого репозитория

Продукт разрабатывается на реальных встречах, поэтому личные данные не
пускают в публичный репозиторий три рубежа: fail-closed локальный
pre-commit (сам список маркеров живёт вне репозитория), проверка автора
коммита и CI-рубеж по форматам, работающий и на PR из форков.

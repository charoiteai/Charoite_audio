# Политика безопасности

*[English](../../SECURITY.md) · **Русский** · [中文](../zh/SECURITY.md)*

Charoite работает целиком на машине пользователя, поэтому большая часть
классической веб-поверхности атак к нему неприменима — но баги в
обработке аудио, файловых путях или локальных HTTP-вызовах всё равно
значимы для безопасности.

**Сообщайте об уязвимостях приватно** через GitHub: Security → Report a
vulnerability (приватный advisory) или письмом на charoiteai@gmail.com.
Не заводите публичные иссью по проблемам безопасности.

Ответа можно ждать в течение нескольких дней. Поддерживаемая версия:
`main`.

## Модель угроз в один абзац

Актив — собственные встречи пользователя: записи, стенограммы и
построенный по ним граф знаний. Серверной части нет. Поверхность атаки,
которая остаётся: данные, **покидающие** машину (опциональный облачный
слой); чужие слова, **входящие** в модели (prompt injection из
стенограмм); канал **обновлений и зависимостей**; и баги, способные
локально угробить запись. У каждой — своя защита ниже.

## Что покидает машину

- **По умолчанию — один запрос: ежедневная проверка версии.** Публичный
  GET на api.github.com за номером свежего релиза — без токена, без
  данных о вас и ваших встречах; выключается `sufler.check_updates: false`
  и рубильником `CHAROITE_NO_CLOUD`. Всё остальное работает на localhost:
  STT, диаризация, LLM и эмбеддинги. `src/privacy.py` — единственная
  инстанция для каждого выхода, способного унести данные встреч, и
  согласием считает только явное `true` в конфиге.
- **Облачный слой включается по-способностям, и ключи вложены.**
  `cloud_live` открывает ответы в темпе встречи (`cloud_hints` работает
  только поверх него). `cloud_enrich` открывает пост-встречную ревизию —
  и под этим же ключом идут ночные ревизии графа: ревизия ядер и ревизия
  досье ночью отправляют собранный из графа текст в Anthropic.
  `cloud_edit_graph` (поверх `cloud_enrich`) — единственный ключ с правом
  записи; файлы сначала бэкапятся, границы контролируются после, а право
  записи снимается всякий раз, когда бэкап снять не удалось.
  `CHAROITE_NO_CLOUD=1` — рубильник, перекрывающий любой конфиг на каждом
  пути. Полная таблица ключей: [PRIVACY.ru.md](PRIVACY.md).
- CLI подписки запускается с вычищенным из окружения `ANTHROPIC_API_KEY`.

## Prompt injection

Стенограммы встреч, ядра и досье — чужие слова, поэтому каждый headless
`claude -p`, который запускает приложение, изолирован. Вызовы «только
текст» несут запретительный список, покрывающий все файловые, командные
и сетевые инструменты сегодняшнего CLI, плюс `--setting-sources ""` и
`--strict-mcp-config` (`cloud.text_only_args()`) — последнее важно:
без него на эти вызовы действовали бы собственные allowlist'ы хозяина
машины из `~/.claude/settings.json`. Честные границы: это запретительный
список, пополняемый вместе с CLI, а не гарантия уровня allowlist.
Единственный вызов, законно трогающий файлы (пост-встречная облачная
ревизия), получает права от явного privacy-ключа и ту же изоляцию
настроек — и лишается права записи всякий раз, когда не удался
пред-правочный бэкап. `tests/test_cloud_isolation.py` сканирует `src/` и
`scripts/` на identifier-вызовы — страховка для типового случая, а не
доказательство.

## Запись — fail-closed

Идущая запись — самый ценный локальный актив, поэтому операции вокруг неё
отказывают в безопасную сторону: встроенный апдейтер перепроверяет живую
запись непосредственно перед подменой бандла, а его helper отказывается
трогать установку, пока процесс приложения жив; файлы записи настольного
демона открываются эксклюзивно (`"xb"`), и коллизия имён — видимая
ошибка, а не тихая перезапись; на остановке звук передаётся атомарными
переименованиями. Компаньоны на iOS и Android пишут штатными рекордерами
платформ и гарантии эксклюзивного открытия пока не дают. Механика:
[ARCHITECTURE.md](ARCHITECTURE.md), «Как встреча переживает падение».

## Supply chain и целостность релизов

- Все workflow работают с минимальными `permissions:` и
  `persist-credentials: false`; пользовательский ввод попадает в скрипты
  через переменные окружения, а не интерполяцией. В CI zizmor гейтит
  безопасность workflow, dependency review — уязвимости высокой
  серьёзности, CodeQL идёт на push в `main`, на PR и еженедельным кроном
  (пока только Python).
- Actions пришпилены к версионным тегам по задокументированной политике
  (`.github/zizmor.yml`) с одним исключением: два workflow с правом
  записи — `release-please` (админский PAT) и `release-app` (релизные
  ассеты) — пришпилены по SHA коммита. Угон мутабельного тега там достаёт
  до артефактов, которые люди ставят себе, — цена не та, что у
  read-only задачи.
- Встроенный python ставит зависимости из `requirements-runtime.lock` с
  `--require-hashes`: в подписанном бандле ровно то, что записано в
  репозитории, а не то, что PyPI отдал в минуту сборки, — вместе с
  транзитивными пакетами. После правки зависимостей пересобрать lock:
  `scripts/lock_runtime_deps.py`.
- Веса моделей сверяются по sha256 из `scripts/get_models.py`. Адреса
  ведут на подвижные ссылки (`resolve/main`, ассеты релизов): владелец
  зеркала может подменить файл, не меняя URL, — а файл потом слушает все
  ваши встречи. Расхождение суммы прерывает установку и оставляет решение
  человеку; `--url` (своё зеркало) проверку пропускает — наша сумма к
  чужому файлу неприменима.
- Dependabot еженедельно обновляет actions, swift, gradle и pip.
- Релизы собираются строго с тега релиза. Встроенный CPython пришпилен по
  версии и сверяется по sha256 с опубликованным upstream `SHA256SUMS`;
  `Charoite.app.zip` и `Charoite.dmg` уходят с опубликованными sha256, и
  встроенный апдейтер сверяет контрольную сумму до установки.
- **Известное ограничение:** сборки пока подписаны ad-hoc, и macOS
  блокирует первый запуск — Системные настройки → Конфиденциальность и
  безопасность → *Открыть всё равно* (правый клик → Открыть на macOS 15+
  больше не работает; детали в README). Developer ID и нотаризация — в
  планах; блокер — entitlements hardened runtime для доступа встроенного
  python-демона к микрофону.

## Обезличивание этого репозитория

Продукт разрабатывается на реальных встречах, поэтому личные данные не
пускают в публичный репозиторий три рубежа: fail-closed локальный
pre-commit (сам список маркеров живёт вне репозитория), проверка автора
коммита и CI-рубеж по форматам, работающий и на PR из форков.

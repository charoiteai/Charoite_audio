# Тесты

*[English](../../../tests/README.md) · [**Русский**] · [中文](../../zh/tests/README.md)*

```bash
.venv/bin/pip install pytest pytest-timeout
.venv/bin/python -m pytest tests/ -x -q
```

С установленным pytest-xdist (его версия закреплена в `ci.yml` как
`PYTEST_XDIST_VERSION`) полный набор идёт в несколько процессов, как в CI:

```bash
.venv/bin/python -m pytest tests/ -q -n 4 --dist loadgroup
```

`--dist loadgroup` держит тесты колеса пакета графа (группа `wheel`) в одном
воркере, и колесо собирается один раз.

Потолок на тест (`timeout = 120` в `pyproject.toml`) работает только
с плагином, а `pip install .` его не тянет (как и сам pytest): без
`pytest-timeout` pytest лишь предупредит о неизвестной
опции, и зависший `join` повесит весь прогон — ровно там, где это
мешает больше всего.

Тест колеса пакета графа собирает колесо офлайн, без изоляции сборки, поэтому ему нужен `setuptools` в venv той версии, что закреплена в `env` файла `ci.yml`; venv на Python 3.12 его не содержит. Нет или версия другая — тест падает и называет точную команду (`<тот же python> -m pip install setuptools==<пин>`).

Без сети и без моделей — всё тяжёлое замокано. `conftest.py` изолирует
каждый тест, так что прогон не трогает ваши настоящие данные:

- **Корень данных и граф.** Сессия получает временный корень данных
  (`CHAROITE_ROOT` из шелла откладывается и возвращается после прогона),
  каждый тест — свой в `tmp_path`, а граф — пустая папка в `tmp_path`
  (`CHAROITE_GRAPH_DIR`). Тест, предмет которого сам корень, объявляет это
  маркером `корень_называет_тест` и всё равно обязан назвать временный;
  `настоящий_корень_ревизии` не подменяет корень облачной ревизии.
- **Сеть.** Сокеты закрыты: неожиданный запрос роняет тест через
  `pytest.fail`, который `except Exception` в коде под тестом проглотить не
  может. Сценарии сервера — маршруты по полному адресу; маркер
  `сеть_разрешена` снимает запрет для теста, которому нужен настоящий сокет.
- **Ollama** по умолчанию недоступна; `@pytest.mark.ollama_отвечает("модель", …)`
  заставляет её ответить этим списком моделей.
- **Фоновые потоки.** Падение потока, поднятого тестом, роняет прогон
  (`PytestUnhandledThreadExceptionWarning` — ошибка), поэтому каждый поднятый
  тестом поток join-ится в границах этого теста.

Тест обязан быть способен упасть: `scripts/check_test_assertions.py` (CI и
pre-commit) отвергает тест, в котором нечему упасть, а
`scripts/mutate_check.py` возвращает дефекты в изменённые строки и требует
красного — см. [«Как контрибьютить»](../CONTRIBUTING.md).

Два сторожевых набора, о которых стоит знать: `test_privacy_defaults.py` (молчание в конфиге значит «облака нет») и `test_cloud_call_sites.py` (каждая точка, откуда запрос может уйти с машины, зарегистрирована и проверяется). `test_documented_commands.py` проверяет, что команды из пользовательской документации работают тем интерпретатором, который в них написан; `test_import_boundaries.py` и `test_entry_points_contract.py` держат раскладку кода и контракт запуска каждой точки входа.

У приложений свои тесты рядом с ними: macOS-приложение —
`swift test --filter '^CharoiteAppTests\.'` в `app/` (живые пробы в
`app/Probes` запускаются только руками); iPhone — `xcodebuild … test` на
симуляторе (см. [app-ios](../app-ios/README.md)); Android —
`./gradlew testDebugUnitTest` в `app-android/`.

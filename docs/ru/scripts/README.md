# Скрипты

*[English](../../../scripts/README.md) · [**Русский**] · [中文](../../zh/scripts/README.md)*

Служебные помощники. Всё локально, всё опционально.

- `doctor.py` — одна команда: чего не хватает (venv, модели, конфиг, Ollama) и как починить.
- `import_meeting.py` — импорт записанной встречи (аудио / текст / субтитры Zoom) в архив и граф; аудио `note_`/`diary_` уходит в конвейер заметок. Сканер папки ждёт, пока WAV дорастёт до размера из RIFF-заголовка, и не расшифровывает ещё копирующуюся запись наполовину.
- `protocol.py` — безопасный протокол для участников из Саммари и Минуток: убирает вики-синтаксис и никогда не включает сырую стенограмму. Есть `--style plain`, `--copy` и `--out`.
- `rename_meeting.py` — согласованно переименовывает стенограммы, архив, заметку графа и статус приложения. По умолчанию сухой прогон, применение — `--yes`.
- `forget_meeting.py` — убирает одну встречу из стенограмм, записи, архива и ссылок графа. По умолчанию сухой прогон, применение — `--yes`; изменяемые выжившие узлы копируются перед правкой.
- `dedup_archive.py` — собирает исторические дубли архивных папок. По умолчанию сухой прогон; `--apply` переносит лишнее в `Встречи-архив/_дубли/`, а не удаляет.
- `dedup_graph.py` — по явному разрешению заменяет побайтовые копии архива жёсткими ссылками. После этого правка через любой путь меняет один файл, поэтому сначала читайте отчёт.
- `memory_bench.py` — бенчмарк всего контура поиска на демо-графе (`--demo`, `--demo-en`).
- `tier3_cores.py` — ревизия ядер (слияние дублей) с `--apply`; без него — прогон вхолостую.
- `nightly_dossier.py` — инкрементально пересобирает досье или показывает результаты поиска через `--find`.
- `morning_brief.py` — сборка утреннего брифа из графа и ночной ревизии.
- `nightly.sh`, `nightly_claude_cores.py` — ночной цикл: tier3 + опциональная облачная ревизия ядер (выключена, пока не включён облачный слой).

Скрипты с зависимостями запускаются через `.venv/bin/python`; `doctor.py` —
осознанное исключение, он работает системным `python3` ещё до установки.
Рабочая последовательность и порядок восстановления описаны в
[практическом руководстве](../USER_GUIDE.md) и
[карте данных](../DATA_AND_RECOVERY.md).

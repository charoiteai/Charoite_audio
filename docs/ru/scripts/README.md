# Скрипты

*[English](../../../scripts/README.md) · [**Русский**] · [中文](../../zh/scripts/README.md)*

Служебные помощники. Всё локально, всё опционально.

- `doctor.py` — одна команда: чего не хватает (venv, модели, конфиг, Ollama) и как починить.
- `import_meeting.py` — импорт записанной встречи (аудио / текст / субтитры Zoom) в архив и граф; аудио `note_`/`diary_` уходит в конвейер заметок. Сканер папки ждёт, пока WAV дорастёт до размера из RIFF-заголовка, и не расшифровывает ещё копирующуюся запись наполовину.
- `protocol.py` — безопасный протокол для участников из Саммари и Минуток: убирает вики-синтаксис и никогда не включает сырую стенограмму. Есть `--style plain`, `--copy` и `--out`.
- `rename_meeting.py` — согласованно переименовывает стенограммы, архив, заметку графа и статус приложения. По умолчанию сухой прогон, применение — `--yes`.
- `forget_meeting.py` — убирает одну встречу из стенограмм, записи, архива и ссылок графа. По умолчанию сухой прогон, применение — `--yes`; изменяемые выжившие узлы копируются перед правкой.
- `dedup_archive.py` — собирает исторические дубли архивных папок. По умолчанию сухой прогон; `--apply` переносит лишнее в `Встречи-архив/_дубли/`, а не удаляет.
- `dedup_graph.py` — по явному разрешению заменяет побайтовые копии архива жёсткими ссылками. После этого правка через любой путь меняет один файл, поэтому сначала читайте отчёт.
- `merge_graphs.py` — сшивает расколовшийся граф. Без `--apply` показывает план; перед применением проверяет все коллизии, автоматически склеивает только Markdown, создаёт резервную копию и откатывает частичный сбой.
- `memory_bench.py` — бенчмарк всего контура поиска на демо-графе (`--demo`, `--demo-en`).
- `tier3_cores.py` — ревизия ядер (слияние дублей) с `--apply`; без него — прогон вхолостую.
- `nightly_dossier.py` — инкрементально пересобирает досье или показывает результаты поиска через `--find`.
- `morning_brief.py` — сборка утреннего брифа из графа и ночной ревизии.
- `nightly.sh`, `nightly_claude_cores.py` — ночной цикл: tier3 + опциональная облачная ревизия ядер (выключена, пока не включён облачный слой).
- `nightly_dossier_review.py` — облачный проход по досье, собранным локальной моделью: Opus видит то, чего не видит пересказ (решение отменено более поздним, срок протух, два узла говорят разное). `--dry` показывает, не записывая.
- `cloud_review.py` — запускает облачный разбор встречи с таймаутом и явными границами, вместо «запустили `claude` фоном и на этом всё». Падение или обрыв больше не оставляют файл ревизии, который лишь выглядит настоящим.
- `get_models.py` — модели одной командой: `--diar` (эмбеддер диаризации, без него живые метки по голосам не включаются), `--segmentation`, `--stt sensevoice` (китайское распознавание, 228 МБ). Ещё `--list`, `--check`, `--url`.
- `diar_bench.py` — DER диаризации: доля времени речи, подписанной не тем голосом. `--make` собирает синтетический фикстур локально — записей встреч в этом репозитории быть не может.
- `stt_bench.py` — CER распознавания: доля символов, пришедших не теми. `--compare` прогоняет SenseVoice против Whisper на одних и тех же синтезированных фразах. Оговорка та же, что у диаризации: синтезированная речь чище живой, это нижняя планка, а не бенчмарк.
- `fix_action_items.py` — разовая нормализация формата поручений в минутках, написанных до того, как демон стал их нормализовать; меняется только формат. По умолчанию сухой прогон.
- `check_private_markers.py` — страж обезличивания (pre-commit-хук): проверяет и добавленные строки, и всё дерево под учётом git, печатает места и никогда сам маркер. См. [Как контрибьютить](../CONTRIBUTING.md).
- `build_embedded_python.sh` — собирает переносимый python-контур, который едет внутри `Charoite.app`; запускается перед `app/make_app.sh` при своей сборке.
- `build_app_icon.sh` — иконка macOS-приложения из документа Icon Composer `app/Resources/AppIcon.icon`: `actool` (Xcode 26+) даёт `Assets.car` для macOS 26 (без него Tahoe рисует старый `.icns` в серой плитке) и legacy `AppIcon.icns` для macOS ≤ 15; оба лежат в репозитории, CI на macos-15 их не пересобирает.

Скрипты с зависимостями запускаются через `.venv/bin/python`; `doctor.py` —
осознанное исключение, он работает системным `python3` ещё до установки.
Рабочая последовательность и порядок восстановления описаны в
[практическом руководстве](../USER_GUIDE.md) и
[карте данных](../DATA_AND_RECOVERY.md).

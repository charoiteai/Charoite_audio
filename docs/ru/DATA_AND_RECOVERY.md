# Данные, хранение и восстановление

*[English](../DATA_AND_RECOVERY.md) · **Русский** · [中文](../zh/DATA_AND_RECOVERY.md)*

Чароит local-first не только потому, что модели запускаются локально. Его
рабочее состояние — обычные файлы, которые можно увидеть, скопировать и
восстановить без закрытой базы данных. Но у одной встречи несколько слоёв с
разными сроками жизни. Эта карта помогает не принять временный файл за архив
и не удалить единственный источник для повтора.

## Карта данных одной встречи

| Место | Что хранится | Срок | Роль |
|---|---|---|---|
| `recordings/` | Раздельные PCM/WAV-каналы микрофона и системного звука | `record_keep_days`, по умолчанию 2 дня | Страховочный источник для точной пересборки |
| `transcripts/` | Живая и финальная стенограммы, минутки, подсказки, разбор | Пока не удалить явно | Рабочий источник конвейера и ручного повтора |
| `<graph_dir>/Встречи/` | Заметка-эпизод со связями и фактами | Постоянно | Каноническая память встречи в графе |
| `<graph_dir>/Встречи-архив/` | Читаемая папка встречи: саммари, минутки, стенограмма и другие слои | Постоянно | Результат для Finder, Obsidian и синхронизации |
| `<graph_dir>/Документация/` | Копии документов, на которые ссылаются узлы графа | Постоянно | Источники графа |
| `logs/meeting-status/` | Состояние обработки, путь к стенограмме, ошибка | 14 дней | Источник состояния приложения и окна «Последние встречи» |
| `~/Library/Application Support/Charoite/semantic_index_v2.bin` | Производный поисковый индекс | Перестраивается | Ускорение поиска, не резервная копия |

`record_keep_days` удаляет аудио, но не документы встречи. Исчезновение строки
из окна «Последние встречи» тоже ничего не удаляет: истёк только служебный
статус.

## Что считать источником истины

- Для долговременной памяти источником истины служит Markdown в `graph_dir`.
  Векторный индекс и история интерфейса производны и могут быть пересозданы.
- Для повторной обработки нужен файл в `transcripts/`. Пока он существует,
  конвейер можно запустить снова без живой сессии.
- Для наиболее точной пересборки нужна ещё свежая запись из `recordings/`.
  После её автоматического удаления останется текст, но заново распознать
  спорный фрагмент из аудио будет уже нельзя.
- `Встречи-архив` — удобный слой чтения. При `sufler.dedup_files: true`
  некоторые его файлы могут быть жёсткими ссылками на оригиналы из
  `Документация/`: правка через любой из двух путей меняет одно содержимое.

Поэтому безопасное правило простое: править итоговые заметки можно, а вручную
перемещать или переименовывать слои встречи лучше через предусмотренные
команды или интерфейс.

## Что удаляется автоматически

Автоматическая уборка ограничена данными, которые заявлены как временные:

- PCM/WAV в `recordings/` старше `audio.record_keep_days`;
- графовые диагностические логи `logs/graph_*.log` по тому же сроку;
- статусы обработки старше 14 дней.

Уборка аудио выполняется при старте демона. Это означает две вещи:

1. файл может физически лежать дольше срока, пока Чароит не запускался;
2. после следующего запуска просроченное аудио может исчезнуть сразу.

Стенограммы, саммари, минутки, задачи и узлы графа автоматически по этому
сроку не удаляются.

## Особый случай: импортированный файл

`scripts/import_meeting.py` сохраняет исходное аудио рядом с материалами
встречи в графе. Эта копия нужна для будущей пересборки, но находится уже не
в `recordings/` и не подпадает под `record_keep_days`. Если граф синхронизирует
iCloud, исходник также может попасть в iCloud.

При политике «аудио живёт два дня» импортированные исходники нужно удалять
отдельно после проверки результата или забывать встречу целиком.

## Минимальная резервная копия

Для восстановления после потери диска достаточно сохранять:

1. весь `graph_dir` — постоянная память и итоговые документы;
2. `transcripts/` — возможность повторить обработку;
3. `config/config.yaml` — выбранные пути, модели и правила;
4. при необходимости повторного распознавания — ещё не истёкшие
   `recordings/`.

Репозиторий и модели можно скачать заново. `logs/`, поисковый индекс и сборку
приложения обычно копировать не нужно. Конфиг может содержать рабочие пути и
настройки приватности, поэтому его резервную копию нужно защищать так же, как
граф.

Перед крупной правкой графа полезна обычная файловая копия или коммит в вашем
приватном Git-репозитории. Charoite не заменяет Time Machine и не управляет
версиями пользовательских ручных правок.

## Восстановление по симптомам

| Симптом | Что ещё цело | Следующий шаг |
|---|---|---|
| Ошибка после «Стоп» | Обычно стенограмма и запись | Открыть стенограмму, затем нажать «Повторить» |
| «Обработка» не меняется | Статус мог остаться от умершего процесса | Запустить `doctor`, затем повторить |
| Статуса нет, стенограмма есть | Интерфейс потерял только служебную запись | Запустить `rebuild_transcript.py` вручную |
| Остался PCM после аварии | Сырая запись и живая стенограмма | Следующий старт демона подберёт встречу; не удалять PCM |
| Есть только WAV/M4A/VTT/SRT | Исходник встречи | Импортировать через `import_meeting.py` |
| В архиве две папки одной встречи | Документы обычно целы в обеих | Сначала сухой прогон `dedup_archive.py`, затем `--apply` |
| Поиск не находит известный факт | Markdown может быть цел, индекс производен | Проверить файл и перестроить поиск новым запросом; индекс не считать источником |

Базовая диагностика:

```bash
python3 scripts/doctor.py
```

Ручная пересборка существующей стенограммы:

```bash
.venv/bin/python src/rebuild_transcript.py transcripts/<файл>.md
```

Импорт сохранившегося источника:

```bash
.venv/bin/python scripts/import_meeting.py <аудио|текст|субтитры>
```

## Безопасные обслуживающие команды

Команды, меняющие данные, сначала умеют показать план.

Переименовать встречу согласованно:

```bash
.venv/bin/python scripts/rename_meeting.py 2026-08-03_1130 "Новая тема"
.venv/bin/python scripts/rename_meeting.py 2026-08-03_1130 "Новая тема" --yes
```

Собрать старые дубли архивных папок:

```bash
.venv/bin/python scripts/dedup_archive.py
.venv/bin/python scripts/dedup_archive.py --apply
```

При применении лишние папки не стираются, а переезжают в
`Встречи-архив/_дубли/` для ручной проверки.

Забыть встречу целиком:

```bash
.venv/bin/python scripts/forget_meeting.py 2026-07-15
.venv/bin/python scripts/forget_meeting.py 2026-07-15_1400 --yes
```

Первый запуск только перечисляет затрагиваемые файлы. `--yes` удаляет встречу
из стенограмм, записи, архива и графа; выжившие узлы перед удалением ссылок
копируются в `.forget_backup/`. Это не корзина удалённой встречи: собственные
файлы встречи после подтверждения нужно считать удалёнными.

## Чего не делать во время восстановления

- Не запускать два ручных `rebuild_transcript.py` для одной встречи.
- Не удалять PCM/WAV только потому, что он выглядит как технический файл.
- Не копировать растущий WAV в папку импорта повторно: дождитесь завершения
  первой копии.
- Не править JSON в `logs/meeting-status/` как способ «сделать встречу
  готовой»: статус сообщает о результате, но не создаёт его.
- Не удалять поисковый индекс в надежде вернуть отсутствующий Markdown:
  индекс производен и не содержит полной копии графа.

Для ежедневной работы достаточно помнить три уровня: `recordings/` даёт шанс
перераспознать, `transcripts/` — повторить конвейер, `graph_dir` — сохранить
долговременную память.

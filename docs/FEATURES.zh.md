# 功能特性

*[English](FEATURES.md) · [Русский](FEATURES.ru.md) · **中文***

## 会议期间

- **实时逐字稿** — 发言合并为按说话人划分的段落，而不是原始的 3 秒片段；轻量模型在段落内部重新划分发言边界，不改动任何一个字（严格校验）。
- **实时说话人分离** — 从最初几秒起即按声音标注“说话人 1/2/…”。绝不猜测机主的姓名；你的麦克风以你配置的名字标注。
- **实时姓名** — 一旦有人自我介绍（或被点名并作出回应），其标签就被替换为姓名——在整个逐字稿中追溯生效，并用于之后的全部发言。姓名必须在文本中逐字出现，以此杜绝幻觉。
- **即时回答（⚡）** — 通过 STT 标点与引导词检测对方提出的问题；约 2-3 秒内送达一条现成的第一人称回答，问题显示在其上方。
- **云端回答（☁️，需手动开启）** — 同一问题并行发给 Claude（你的订阅，`claude` CLI）：本地即时应答，云端在 10-20 秒后给出更深入的回答。默认关闭——且在每条路径上都关闭：该开关由 `src/privacy.py` 读取，并在实际启动 `claude` 的线程内部校验，因此手动请求（⌘⇧⏎）也无法绕过。该层关闭时按钮置灰并说明原因；`SUFLER_NO_CLOUD=1` 无论配置如何都强制关闭。提示词只携带你的角色，绝不携带话题列表，并要求诚实优先于自信：会议事实（议程、数字、状态）来自逐字稿，否则声明为未知——过去在会议初期，预置话题的提示词曾让模型把那些话题当作实际议程来呈现。
- **自动要点** — 随对话推进生成 📌 事实/决定、💎 亮点、💭 想法；重量级模型定期复审（🔬）。换述的重复项由本地 NLI 模型过滤（重复 = 相互蕴含；带来新事实的细化不算重复）。该层可选：`models/nli/` 中没有模型时它就直接关闭——见 src/nli.py。
- **似曾相识（⏮）** — 当对话触及某个“核心”（知识图谱中的跨会议话题）时，会送来一条要点：“⏮ 7 月 15 日讨论过，当时状态为……”。语义匹配（bge-m3 嵌入向量，相对阈值），而非字面词语。
- **会议开始时的自动简报（⏮）** — 最初几句发言揭示话题后，守护进程一次性拉取档案上下文：排名靠前的核心及其状态与最近讨论日期。由知识图谱中现成的行拼装而成，不经 LLM——即时呈现，也无从产生幻觉。配置项：`meeting_brief`。
- **实时会议纪要草稿** — 约每 2.5 分钟刷新一次；最终纪要按需生成，或在停止后生成。
- **向助手提问** — 会议中途输入问题：回答优先基于实时逐字稿构建，其次是知识图谱记忆，最后是模型自身知识（并标注来源）。

## 会议结束后（自动）

1. **逐字稿重建** — 对完整录音按声道重新做说话人分离：回声过滤、细碎片段合并、整洁的段落、姓名标注。
2. **知识图谱更新** — 实体（人物/系统）、决定、行动项、带状态与编年记录的核心；外加一份带 wiki 链接的会议笔记。
3. **会议档案** — 一个“日期 — 标题”文件夹，内含全部文档，以及一个在 Obsidian 中打开知识图谱的链接。
4. **摘要** — 一分钟读完：结论先行 → 话题 → 决定 → 行动项（谁/做什么/何时）→ 待解问题 → **与过往会议的关联**（“此前：……（7 月 15 日）→ 今天：……”）→ 深入导航。
5. **复盘**（可选）— 会议问答、任务、针对待解问题的备选方案、对下次会议的建议。

**核心修订**（`src/tier3.py`）— 随着时间推移，抽取器会把同一个反复出现的话题拆成一对孪生核心。修订流程负责找出这类配对——嵌入向量预筛（bge-m3）→ NLI 裁判——并自行运行：每次会议后增量执行（本次会议的核心对照全部核心），也可通过 `scripts/tier3_cores.py --all-graphs --auto` 做全量扫描（愿意的话可挂到 cron——`--auto` 仅在 `tier3_auto_apply: true` 时才合并，否则只做标记；`--apply` 保留给手动运行）。权限分两级，因为改动的代价不同。可逆改动总是执行：中等置信度的配对会得到“疑似重复”标注（晨间简报把这些汇总为“Tier3 请求你合并”），嵌套关系（“事件 ⊂ 流程”）只做交叉链接，绝不合并。不可逆改动——合并，即转移编年记录并在重复项原位留下重定向占位——需要 CLI 上的 `--apply` 或配置中的 `sufler.tier3_auto_apply: true`。证据越弱，门槛越高：抽取器生成的核心没有 `## Суть` 小节，因此裁判比较的只是当天的状态行，而同一项目的两个进行中任务在状态行上读起来十分相似。对这样的配对，仅有把握十足的判定还不够——两者的编年记录还必须互不相交：孪生核心来自*不同*的会议（6 月对该话题用一种叫法，7 月用另一种），而同一项目的两条线索会贯穿同一批会议。编年记录有交集的配对只标记，不合并。通用的“枢纽”核心永不改动，且每次写入之前都会先备份到 `Ядра/.tier3_backup/`。

**主题档案**（`src/dossier.py`、`scripts/nightly_dossier.py`）——为每个贯穿性
主题生成一份综述：当前状态、时间线、已定事项、未决问题、相关人员，每一条都链接
到来源节点。主题簇 = 一个核心 + 所有指向它的节点；边界来自人工已经画好的链接。
检索**优先**查询 `Dossiers/_index.json`，只在需要细节时才进入图谱，因此"这个主题
现在怎么样"由一份写好的综述回答，而不是十几个片段。重建是增量的：档案带有其来源
的指纹，指纹未变则不调用模型。手工补充写在 `## 作者修改` 小节，重建时保留。查看
某个查询会命中什么：`scripts/nightly_dossier.py --find "你的问题"`。

**云端档案复核——可选**（`scripts/nightly_dossier_review.py`）。本地模型批量且低成本
地生成档案，但看不出关联：某个决定已被推翻、某个期限已过、两个来源互相矛盾。Opus
能看出来，作为第二遍运行。当 `sufler.cloud_edit_graph: true` 时它直接修改；**默认
关闭**，此时只写出 `Service_dossier_review_<日期>.md`，由人来应用修改。两种模式下
会议记录、纪要和 `## 作者修改` 均不触碰；每次修改前先备份到 `Dossiers/.backup/<日期>/`。

**夜间循环**（`scripts/nightly.sh`，可挂到 cron/launchd）：Tier3 修订 → **晨间简报** → **记忆基准测试**。夜间修订仅在 `sufler.tier3_auto_apply: true` 时才合并核心；没有该键则止步于可逆标记——不可逆改动的权限放在配置里，而不在排程里。晨间简报（`scripts/morning_brief.py`）向每个知识图谱写入 `_Сегодня.md`——最近的会议配单行梗概、取自摘要的已定事项/任务/待解问题、进行中的核心与合并提示；由知识图谱中现成的行拼装而成，不经 LLM——在第一个问题到来之前，用一分钟读完你的晨间上下文。记忆基准测试（`scripts/memory_bench.py` + `config/memory_bench.yaml`，格式见示例文件）把参考问题跑过真实的 RAG 流程，并检查回答中是否出现必备事实——调整阈值/提示词后的退化会显现在夜间日志里，而不是在真实会议中。各步骤相互独立——修订失败不会取消简报——但只要任一步骤失败，整次运行就以非零码退出：过去该任务以一条 `echo` 收尾，即便某晚什么都没发生，launchd 也照样报绿。基准成绩下滑只是日志里的警告，不算失败：它提示退化，但不会中断循环。

- **档案文件夹名称包含会议时间** — «2026-07-24 11-30 — 主题»：一天五场会议一眼可辨，何况重新处理后文件夹的 mtime 本就不可信。旧格式的文件夹会在下次更新时自动迁移。

## 会议之外

- **听写**（全局快捷键）— 开口说 → 本地识别 → 粘贴进当前活动输入框；剪贴板随后恢复原样，包括图片。
- **导入已录制的会议** — `scripts/import_meeting.py file`（音频 m4a/wav/mp3，文本 txt/md，来自 Zoom/Teams 的字幕 vtt/srt——保留说话人姓名）→ 生成完整会议档案：逐字稿、会议纪要、复盘、要点、知识图谱；会议日期通过 `--date/--time` 指定；源文件保存在会议材料旁边（APFS 克隆）。
- **实时会议上下文** — 话题在通话开始几分钟后才浮现；守护进程从实时逐字稿中提炼话题、检索档案，并在提示的提示词中重建«过往会议»区块：提示、即时回答和问答看到的是关于当前话题的旧约定，而不只是最近两场会议。本地运行，默认开启（`sufler.live_context`）。
- **云端润色提示** — 提示采用阶梯模式：本地模型即时应答，随后云端模型（Claude CLI，默认 Haiku）把«☁️ …»直接追加到同一张提示卡片上（过时的润色只进提示日志）。每次提示都会把逐字稿发送到云端——单独开关，默认关闭（`sufler.cloud_hints`）。
- **开场简报** — 会议开始时提示卡片不再空白：显示来自档案的上次会议话题、达成的决定和未完成任务数——即时呈现，仅解析文件，仅限主知识图谱。
- **iPhone 伴侣应用（v1，app-ios/）** — 手机录制会议/笔记/日记条目；在 iCloud Drive 中一次性选定投递文件夹（文件夹按钮）——就是 Mac 监视的那个导入文件夹。不会丢失任何内容：Documents 中的设备端队列会在每次启动时重发。`note_*`/`diary_*` 文件被路由到笔记管线。锁屏时仍可后台录音。构建：在 app-ios/ 中执行 `xcodegen generate`，在 Xcode 中签名。

- **导入文件夹（受监视）** — 给应用指定一个文件夹（设置 → 导入，或 CLI 的 `--scan`）：丢进去的录音会自行变成知识图谱中的会议；处理完的文件移入 `done/`，失败的仍留在原处可见。
- **替换词典** — STT 会弄错领域术语和人名；配置中的 `sufler.vocabulary` 以声明式方式修正它们（不区分大小写，仅匹配整词），对实时会议、听写、笔记和导入同样生效。
- **会后钩子** — `sufler.post_meeting_hook`：每场会议（实时或导入）结束后运行你的命令，环境变量中带有 `SUFLER_TRANSCRIPT` 和 `SUFLER_STAMP`——webhook 的本地版。
- **日记（⌥⌘J）** — 说出一个想法 → 在个人领域 `Дневник/YYYY-MM-DD.md` 的«## HH:MM»之下生成条目：你的话语（带标点）、想法、复选框任务（在任务窗口中可见）、原始的“口述原文”；谈及今天会议的想法会附上指向该会议的链接——反向链接把各领域连起来，而正文仍留在日记里。个人条目绝不会漏入工作检索。
- **语音笔记** — 说出一个想法 → 模型整理文字、加上标题、提取任务 → 在知识图谱中生成文件（`Notes/`）+ 存入记忆。原始文本保留在旁（“口述原文”）。

- **英文文档** — `sufler.language: en` 把会议纪要、摘要、即时回答和知识图谱节点内容切换为英文（已在英文逐字稿上验证）；提示使用你角色的语言。
- **一键夜间循环** — 设置中一键安装 04:15 的 launchd 任务（带备份的核心修订、晨间简报、记忆基准测试）；同一按钮也可将其移除。
- **录制提醒**（需手动开启）— 会议开始时显示系统通知和窗口内提示条，提供明确的「开始录制」与「暂不」操作。录制绝不会自行开始。可选的登录时启动使用 macOS「登录项」，即使尚未打开窗口也能提醒。
- **日历简报**（需手动开启）— 设置中的开关：下一场会议开始前，悬浮条显示带会议标题的按钮，一键生成档案简报。仅读取最近一个日程的标题与时间，且在本地完成。
- **自定义会议纪要模板** — config.yaml 中的 `sufler.minutes_template`：用你自己的 markdown 骨架替换默认小节。
- **会议任务** — 会议纪要把分派事项写成复选框（«- [ ] **姓名** — 做什么 — 何时»）；任务窗口收集整个知识图谱中的所有 `- [ ]` 并显示未完成数量角标，勾选即把 `[x]` 直接写回 markdown——Obsidian 与应用始终一致。
- **流式档案回答** — 约 1 秒出首词，逐 token 输出并带打字光标；聊天模型选择器列出的正是 Ollama 实际已有的模型。
- **回答历史** — 过往问答折叠在当前回答之下，重启后依然保留（磁盘最多 50 条）。
- **档案问答与简报** — 搜索 v2：俄语形态词干化、IDF（罕见查询词权重更高）、查询覆盖率、文件新鲜度、知识图谱提炼内容排在原始逐字稿之前、结果多样性（单场会议不再占满全部名额）。弱匹配会被标注“⚠ 档案中可能没有”——助手不会用无关片段拼凑答案。回答来源可点击（在 Obsidian 中打开）。配合可选的 brain 伴侣服务（:8100），bge-m3 语义层即使没有词面重合也能找到答案。

## 文档格式

一切都是纯 markdown，无需渲染即可阅读：以加粗键名的列表代替表格、短小的区块、每次都相同的结构、要点先行（BLUF）。层级：摘要（1 分钟）→ 会议纪要 → 复盘 → 逐字稿。

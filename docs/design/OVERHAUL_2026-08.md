## 0. Принцип: не «глобальный рефакторинг», а партии

Big-bang на живом продукте запрещён: демон пишет встречи владельца
ежедневно, а канонический опыт индустрии (strangler fig, AWS/Fowler)
прямо говорит — «переписать всё разом» значит месяцы без фич и
регрессии; «полу-задушенный монолит — Франкенштейн» (Heureka, 2025).
Наша собственная практика партий (живой контур A–D, SCK #383, панель
#394) — это и есть рабочая форма. Правило кругов действует для каждой
партии как для обычного PR; правило «второй Critical подряд → упрощать»
— тем более.

## 3. Внешний ресёрч — что берём, что нет

- Python-демоны: threads для блокирующего I/O — канон; наша модель
  верна. Урок про daemon-threads и abrupt shutdown — у нас есть finally
  и flock-локи; free-threading 3.14 — наблюдать, не трогать.
- SwiftUI-2026: дефолт — MVVM + @Observable, «архитектура по шерсти
  платформы»; TCA — НЕ брать (сторонняя, против SwiftUI-зерна, для
  больших команд). Наш паттерн «чистые политики + тонкие вью» — родной
  аналог LUCA-подхода; расширять его, не менять парадигму.
  SPM-модуляризация по bounded context — кандидат ПОСЛЕ партий.
- Strangler fig: инкременты с сохранением поведения, «убивай начисто
  или не берись» — партия не считается закрытой, пока старый путь не
  удалён.
- Аналоги (Meetily, ownscribe, OpenWhispr): наш стек канон; наше
  преимущество — cross-meeting identity (канон имён + узлы Люди),
  которого «из коробки нет ни у кого». Исследовать отдельно:
  unified-модели транскрипции+диаризации одним весом
  (MOSS-Transcribe-Diarize, 50+ языков, 90 мин без сегментации) —
  потенциальная замена пары whisper+позиционная диаризация.

## 4. Позиция ведущего (Claude)

1. daemon.main() в классы НЕ переписывать — продолжать выносы чистых
   решений (доказано метрикой мутатора 53/53 → 4/41). MeetingRuntime —
   только механический вынос состояния, циклы не трогать.
2. Codex P0 (характеризационные тесты) — ПЕРВАЯ партия всего плана:
   сеть до ножа.
3. Ключ подписи релиза — никогда в CI (согласен с Codex; это
   архитектурный инвариант, не неудобство).
4. Автоматы остановки/захвата и meeting_stamp — не трогать (единодушие
   голов; стабилизированы кровью кругов).
5. Слияние live/offline владельца — только общие примитивы; финал
   остаётся независимой переоценкой.
6. DI-контейнеры, TCA, микросервисы, переписывание на asyncio — НЕ
   делать: цена выше выигрыша для соло-продукта, поддержанного головами.
7. Лимит 1000 строк дал файл-шов (SuflerCaptureLoss) — лечить
   владельцами состояния, а не механическими разрезами; сам лимит
   оставить.
8. Ритм: 1–2 партии в неделю параллельно с фичами, не спринт «всё
   бросили и рефакторим». Метрики успеха: churn горячих файлов ↓,
   выжившие мутанты ↓, длина топ-файлов ↓ — а не «красота».

# Сравнение runtime через транспорт Чароита

Первый этап пункта 6: отдельный замер TTFT и полного времени одинаковых
промптов через `LLM.stream`, со штатной обработкой потоков и арендами.
Ни прямого второго HTTP-клиента, ни изменения пользовательского конфига.
Только локальные Ollama и mlx-server на штатных адресах, облака нет.

`CHAROITE_ROOT=/path/to/data python scripts/runtime_profile.py --engine ollama
--model NAME --prompt-file hint.txt --prompt-file minutes.txt --repeats 4`

Для MLX повторить с `--engine mlx-server --model NAME`. Рантаймы запускает
человек заранее; скрипт не скачивает, не выгружает и не перезапускает модели.
Сравнивать одинаковые веса/квантизацию, контекст и лимит ответа; фиксировать
версии runtime отдельно. Иначе это сравнение конфигураций, а не движков.

В JSON сохранены все испытания, хеши входа/выхода, TTFT, полное время,
пустые ответы и ошибки. Первый наблюдаемый вызов отделён, но НЕ назван
холодным: модель могла быть загружена заранее. Медиана/p95 последующих
успешных испытаний показаны рядом с числом отказов. Малый набор даёт лишь
описательную оценку p95, не надёжный прогноз хвостовой задержки.

Перед каждым запросом проверяется лок живой встречи. Если она началась,
новые запросы не запускаются; текущий запрос не вытесняется. Нагрузочное
сравнение одновременно с STT и измерение памяти серверных процессов остаются
следующим этапом. Память Python-клиента не выдаётся за память модели.

# Контракт меток NLI (2026-10)

Какой из трёх логитов ONNX-модели — «следование», берётся из `config.json`
модели (`id2label`), а не угадывается. Годится только перестановка
`entailment`, `neutral`, `contradiction` на индексах 0, 1, 2 (регистр и
пробелы вокруг не важны). Проверка — `nli._label_index`, дешёвая фаза —
`nli._problem` (разбор кэшируется по mtime файла).

Отказ — с причиной, а не молча:

- нет `config.json`, нет `id2label`, метки `LABEL_0…`, дубль или нестроковая
  метка — `is_available()` ложно, `judge().refused` называет файл и причину ещё
  до чтения ядер;
- сессия ONNX не собралась — причина (с подсказкой перезапустить демон)
  пишется в лог один раз и несёт её же каждый отказ `judge().entail`;
- выход модели не из трёх конечных логитов — `SeamTransportError`; дедуп
  тезисов демона считает такую пару, как и любую ошибку судьи, «не дубль».

Где видна причина: демон — один раз строкой `тезис-дедуп выключен: <причина>`
(`nli.refusal()`); ревизия ядер после встречи — `tier3: пропущен — <причина>`;
ночная ревизия (`scripts/tier3_cores.py`) — «ревизия не состоялась — <причина>»;
решающий гейт — `судья: <причина>` в своём отказе.

Установка без `config.json` выключает смысловой дедуп с этой причиной в логе;
вернуть — положить `config.json` из того же экспорта, что и `model.onnx`
(docs/MODELS.md, раздел NLI).

# Диагностика NLI без скрытого инференса

Доктор проверял Nemotron, но не показывал состояние NLI. Теперь годность комплекта берётся из одного источника — `nli.refusal()`, того же ответа, по которому демон включает или выключает смысловой дедуп тезисов. Обычный запуск печатает причину отказа дословно (нет файла, негодные метки или битый `config.json`, нет пакетов) предупреждением; годный комплект — отметкой «годны» с указанием на `--probe-nli`. Отсутствие опционального NLI — предупреждение, не авария всего приложения. Годный комплект не выдаётся за работающий инференс.

`--probe-nli` проверяет только локальный NLI: сначала `nli.refusal()`, затем лок демона, затем `nli.judge()` — отказ судьи (`refused`) печатается дословно, иначе канарейка `ready()`. Конфигурация LLM и её сервер не проверяются; веса не скачиваются. Код 0 означает успешную канарейку; отказ, недоступность и отложенная проба дают код 1. Параметры --probe-nli и --restart-llm взаимоисключающие.

Лок демона проверяется до загрузки модели. Если встреча идёт, проба откладывается. Это проверка на входе: проба не прерывается, если встреча стартовала позже.

Тесты подменяют судью и веса заглушками; качество модели не измеряется. Команда готова для отдельной пробы на машине с моделью.

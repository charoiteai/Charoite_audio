# Поиск приложения: один переход по связям

Первый этап пункта 3: приложение, как демон, может найти факт в документе,
на который ссылается совпавший узел. Из первых двух показанных результатов
берутся исходящие wikilinks, один новый сосед получает слот в общем limit.
Документы уже прочитаны поиском: новых чтений диска и HTTP-запросов нет.

Переход помечен родительским источником. Он не повышает bestCov/bestSim и
не отменяет маркер слабых совпадений. Источники возвращаются после упаковки
в бюджет; отрезанный документ не объявляется использованным.

Неоднозначные короткие имена не разрешаются, только точные квалифицированные
пути. Служебные пути, traversal, циклы и второй переход исключены.
При limit=1 перехода нет. Порядок связей сохранён как в документе.

Ограничение: это исходящая связь, не независимое доказательство релевантности.
Общая реализация ранжирования Python/Swift и калибровка уверенности остаются
следующим этапом. Это не заявление о полном совпадении двух поисков.

Проверка: `cd app && swift test --filter ArchiveLinksTests`.
Интеграционный сценарий ищет человека, а решение находится только в
связанной встрече, без имени человека в тексте встречи.

# Сравнение эмбеддеров и reranker

Первый этап пункта 4 — одинаковые суждения и метрики для любых моделей,
без смены штатного bge-m3. `scripts/retrieval_compare.py` сравнивает два
сохранённых прогона: Recall@k, MRR@k, nDCG@k, ложные ответы и ложные отказы.
Результаты есть по каждому вопросу; пропущенный после ошибки вопрос запрещён.

Суждения: массив `[{"id":"q1","relevant":{"Meetings/One.md":3}}]`.
Пустой relevant — безответный вопрос. Оценки 1–3: от полезного фона до
прямого источника ответа. Досье и первичная встреча оцениваются отдельно.
Прогон: `{"model":"bge-m3/config-hash","results":[{"id":"q1",
"ranking":["Meetings/One.md"],"abstained":false}]}`.
abstained описывает фактическое решение контура отвечать/отказаться;
сам evaluator этого решения по рангу не выдумывает.

Запуск: `python scripts/retrieval_compare.py judgments.json baseline.json
candidate.json --k 5`. stdout — JSON, который можно сохранить в отчёт.
Скрипт не открывает граф, не скачивает модели и не отправляет текст в сеть.

Эксперименты: (1) bge-m3 против Qwen3-Embedding-0.6B; (2) тот же пул
кандидатов с bge-reranker-v2-m3; (3) тот же пул с Qwen3-Reranker-0.6B.
`rerank()` проверяет точное покрытие пула конечными оценками и стабильность
при равных оценках. Добавление/удаление кандидатов не выдаётся за reranking.

Для замены эмбеддера нужен новый индекс, корректный query instruction и
новая калибровка порогов уверенности. Сохранить версии моделей, квантизацию,
размеры блоков, инструкции и время выполнения рядом с каждым прогоном.
Нужен отложенный набор реальных вопросов; демо не доказывает превосходство.
Инференс-адаптеры моделей и экспорт прогонов — последующий этап.

Результат со `status: error` или непустым `error` отклоняет сравнение: сбой транспорта не считается правильным отказом на безответный вопрос. Нужно устранить ошибку и повторить полный набор.

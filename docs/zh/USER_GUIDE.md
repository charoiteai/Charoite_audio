# 用户实用指南

*[English](../USER_GUIDE.md) · [Русский](../ru/USER_GUIDE.md) · **中文***

这不是功能清单——完整功能见[《功能》](FEATURES.md)。本指南按日常流程说明：
准备 Charoite、录制会议、看懂会后处理、取得结果，以及在失败后安全恢复。

## 第一次正式会议之前

1. 完成[安装](SETUP.md)。使用预编译应用时，首次运行向导会询问你的姓名和图谱
   文件夹——无需手动编辑 `config/config.yaml`。从源码运行时，请填写
   `sufler.user_name` 与 `sufler.graph_dir`。
2. 也在那里检查就绪状态：Python 运行环境、配置、Ollama、模型、麦克风和图谱
   文件夹。从源码工作时，请在**设置**中指向仓库文件夹——应用会从那里运行代码，
   而不是用自己应用包内的那份。
3. 线上通话无需任何配置：首次录制时 macOS 会请求「屏幕与系统音频录制」权限，
   点击「允许」即可。没有它只能录到您的麦克风。BlackHole 仅在 macOS 13
   之前作为备用方案。
4. 先做一段短测试录音，并等到结果卡片出现。这一次会同时验证声音采集、
   识别、Ollama 和图谱写入。

如果就绪检查没有解释问题，请在仓库根目录运行：

```bash
python3 scripts/doctor.py
```

`doctor` 不只检查安装，还会实际测试模型生成、未完成会议、导入队列和磁盘
空间。它只报告，不会自行修改任何内容。

## 每场会议之前

- 菜单栏应显示**“可以录音”**，而不是“Ollama 无响应”。
- 音源由 Charoite 自行选择并在开始后显示：「系统音频（ScreenCaptureKit）」
  为常规路径，「BlackHole」为备用。无需切换系统输出设备。
- 告知参会者正在录音。Charoite 不会让机器人加入会议，也无法代替你完成告知。
- 启用日历集成后，应用会询问是否开始录音，但绝不会自动开启录音。

## 会议进行时

在主窗口按**“听取会议”**，或在菜单栏按**“开始录音”**。红点与不断增加的
计时器表示会话正在运行。

不要只看计时器，也要检查最初几行逐字稿：

- 麦克风声道应标成配置中的你的姓名；
- 对方应出现在另一个声道，或显示为“说话人 N”；
- 如果没有系统声音，必须当场修复——事后无法只从麦克风恢复对方声音；
- 如果出现“磁盘录音已关闭”，实时逐字稿仍会继续，但失去了用于精确重建的
  保险音频。

主窗口可以关闭，状态仍留在菜单栏。录音中退出应用会要求确认，因为退出会
停止本次会议。

忘记停止并不可怕：录音会自行结束——若从头到尾无人说话，5 分钟后停止；
交谈结束后陷入沉默，15 分钟后停止；无论如何 6 小时后停止。还有第四种情况：
若整场录音都没听到对方的声音——系统声道一直安静，只有您在说——沉默按 10
分钟计算，而不是 15 分钟。请注意，线下会议在我们看来是一样的：所有人同处
一室，声音都进入麦克风，也就是说「对方」按定义并不存在。如果您的会议以线
下为主，请设置 `alone_minutes: 15`，该规则便不再改变任何行为；设为 `0`
则完全关闭。结束前一分钟
会出现预告（状态栏；若窗口不可见还会有横幅通知）——说句话录音就会继续。
停止走的是与「停止」按钮相同的常规路径：会议被保存并处理，不会丢失任何
东西，状态栏还会保留停止原因。自动停止管不了的情况：房间里开着的电视或
音乐——那些人声对我们就是交谈，这类录音只能靠 6 小时上限终止。阈值配置见
`config/config.yaml` 的 `sufler.autostop`。

## 按下“停止”之后

处理过程独立于窗口。应用读取流水线的真实状态，不会编造百分比。

| 状态 | 含义 | 该怎么做 |
|---|---|---|
| 正在保存录音 | 声道正在完成写入；必要时把遗留 PCM 转为 WAV | 不要移动 `recordings/` 中的文件 |
| 正在重建逐字稿 | 完整录音重新识别并做说话人分离 | 可以关窗口，但不要让 Mac 关机 |
| 正在更新图谱，第 N/M 部分 | 正在生成纪要、节点、链接、归档与摘要 | 部分编号应继续前进 |
| 会议已就绪 | 图谱笔记与结果卡片已经发布 | 打开卡片或 Obsidian |
| 失败——原始文件已保留 | 流水线没有生成完整图谱结果 | 打开逐字稿并重试 |

处理时长取决于会议长度和模型。成功处理几场之后，Charoite 会按你过去运行的
中位数给出估计。状态 30 分钟未更新时，应用会显示失败，而不是永远转圈。

## 会议结果卡片

卡片直接显示最常用的结果：

- 主题、日期，以及根据逐字稿时间戳估算的时长；
- 从逐字稿中识别到的参会者；
- `Саммари.md` 中的概要、决策和行动项；
- 完整笔记、逐字稿与 Obsidian 入口；
- 复制摘要、任务或整张卡片。

标题旁的铅笔会协同重命名逐字稿、归档文件夹、图谱笔记和状态里保存的路径。
不要在 Finder 中分别重命名这些部分，否则容易留下失效链接。

给参会者发送内容时，请使用清理后的会议协议，而不是原始逐字稿：

```bash
.venv/bin/python scripts/protocol.py --style plain --copy
```

默认选择最新会议，也可传入日期或标题片段。协议包含概要、决策、行动项、开放
问题和风险；无论使用什么参数，都不会包含原始逐字稿。

## “近期会议”不是完整归档

这个窗口最多显示最近 14 天的 20 条处理状态，用于回答“昨天那段录音后来怎样
了”，并不替代图谱归档。

完整历史仍位于 `<graph_dir>/Встречи-архив/` 与 `Встречи/`。状态从窗口过期
不会删除会议文档。全部存储位置和保留规则见
[《数据与恢复》](DATA_AND_RECOVERY.md)。

## 处理没有完成时

按从最安全到更手动的顺序操作：

1. 打开错误状态提供的逐字稿。如果其中有对话，重试所需的源数据仍在。
2. 按**“重试”**。重试进行时，第二次启动会被阻止。
3. 若重试没有开始，运行 `python3 scripts/doctor.py`。常见情况是 Ollama 能列出
   模型，但生成请求本身已经卡住。
4. 按提示重启 Ollama，再从应用中重试。
5. 若状态记录已消失、逐字稿仍在，手动运行：

```bash
.venv/bin/python src/rebuild_transcript.py transcripts/<文件>.md
```

会议就绪前不要删除逐字稿或 `recordings/` 中的新文件。重试从逐字稿开始，
而录音能让重建更加准确。

## 旧录音与手机录音

音频、已有文本或 Zoom/Teams 字幕都能进入同一条流水线：

```bash
.venv/bin/python scripts/import_meeting.py recording.m4a --date 2026-07-15
.venv/bin/python scripts/import_meeting.py zoom.vtt --title "规划会议"
```

也可以在应用设置中指定监视导入文件夹。正在增长的 WAV 会等复制完成后才处理。
导入的原始音频保存在图谱中，不受 `record_keep_days` 约束；备份和删除时要记住
这一区别。

## 会议之间

- **档案**会根据过去会议回答并显示来源。弱匹配警告表示档案里可能没有答案。
- **会议任务**汇总未完成的 Markdown 复选框；勾选后直接写回图谱文件。
- **带记忆的聊天**把检索到的图谱事实加入本地模型上下文。
- **听写**、**语音笔记**和**日记**可从菜单栏通过 `⌥⌘D`、`⌥⌘N`、
  `⌥⌘J` 使用。

最短的日常闭环是：确认绿色就绪 → 开始录音 → 确认双方声音都出现 → 停止 →
等待卡片 → 分享决策和行动项 → 必要时修正标题。

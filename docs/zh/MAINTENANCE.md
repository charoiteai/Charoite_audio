# Charoite 如何维护

*[English](../../MAINTENANCE.md) · [Русский](../ru/MAINTENANCE.md) · **中文***

Charoite 由 AI 在人类指导下维护。本页描述的是真实运转的流程——证据是
提交历史，而不是一场表演。

## 角色

- **人类所有者**设定方向与优先级，制定下述规则，决定何时发布什么，
  负责隐私政策，并对结果负责。
- **AI 维护者**（Claude Code，以 `Charoite AI` 身份提交）编写代码：
  设计、实现、测试、文档、发布——完整闭环。

## 一次变更如何发布

1. 所有者提出任务和重要约束。
2. Claude 实现它——代码、测试和文档在同一次变更中完成。
3. **独立对抗式评审。**每个实质性变更都由未参与编写的第二个头脑检查：
   独立的 Claude 代理，或完全不同的模型（去相关评审）。发现的问题在
   PR 打开前修复并复查。
4. 完整的本地测试套件必须通过（Python 和 Swift——目前合计约 1000 个
   测试）。
5. Pull request 运行必需的 CI：CodeQL、Python 和 Swift 测试、lint、
   供应链检查（zizmor）、文档守卫、提交信息规范以及匿名化闸门。
6. CI 红色则禁止合并。绿色则 squash 合并；release-please 切出带版本
   的发布。

自主的夜间运行确实存在且属常态——它们经过与白天工作相同的评审和 CI
闸门。无论何时，红色流水线上不合并任何东西。

## 流程本身的隐私

产品的承诺——一切不离开你的机器——同样适用于它的构建方式：

- **pre-commit 匿名化闸门**（`scripts/check_private_markers.py`）
  阻止姓名、雇主、内部系统名称和逐字稿片段进入公共仓库。
- 当使用外部模型做去相关评审时，它只能看到**公共树的干净 checkout**
  ——绝不接触用户数据，绝不接触 gitignored 的本地状态（录音、逐字稿、
  配置）。
- 密钥和令牌存放在仓库之外。

## 对贡献者意味着什么

欢迎外部贡献，评审走同一条流水线——见 [CONTRIBUTING](CONTRIBUTING.md)。
安全报告通过 [SECURITY.md](../../SECURITY.md) 提交；阅读它们的是所有
者，而不只是 AI。

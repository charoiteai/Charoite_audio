# Local-first ≠ local-only：为什么图谱由强模型来维护

*[English](../../MANIFESTO.md) · [Русский](../ru/MANIFESTO.md) · **中文***

这是 Charoite 在真实会议上运行数月后的诚实结论。一句话：本地模型已经
能出色地听、搜、分类——但它们还无法维护知识图谱。我们测量了这一点，
接受了它，并围绕这个事实（而不是与它对抗）构建了整个架构。

## 我们从哪里出发

产品的承诺很简单：对话不离开这台机器。语音识别、说话人分离、提示、
档案搜索——全部在笔记本上完成，没有一个网络调用流向外部。我们认真
尝试过把这条线推到底：让本地模型也端到端地维护知识图谱——人物与
系统节点、决策编年史、主题档案。

没有成功。这条边界值得精确描述，因为它并不在网上常见争论的位置。

## 本地模型擅长什么——数字，不是观点

以下全部在一台普通笔记本上离线运行：

- **语音识别。** GigaAM 几乎逐字地转写俄语——控制短语完整返回，至多
  偶尔丢一个专有名词。英文和中文由 Parakeet 和 Whisper 承担（中文还
  可选 SenseVoice），同样纯本地。
- **说话人分离。** pyannote 分段加 ERes2Net 声纹向量。在我们的基准上，
  分离错误率从 0.725 降到 0.246——这是固定音频集上的数字，不是感觉。
- **窄决策。** 一个 4–9 GB 的模型以约 92% 的准确率、三分之一秒的速度
  回答「这需要联网搜索吗」「这是医疗文档吗」这类问题。便宜、即时、
  无云。
- **档案搜索。** 单一向量模型 bge-m3（在我们语料上 93% Top-1），与
  词法搜索经 RRF 融合。语义补词汇断层，词法抓内部行话。
- **实时要点与提示。** 35B MoE 模型在 M1 Max 上每秒约 27 个 token
  （2026-08-08 实测，`num_ctx: 8192`）——比说话速度快好几倍，因此足以
  边听会议边给出提示。

这些都不是妥协。在这些任务上，本地模型并不比云端差——它们是足够的，
而隐私和零延迟是白送的。

## 它们在哪里断裂

知识图谱是另一类工作。合并同一个人的两个重复节点。发现四月决定了 X、
六月决定了相反的事，而两条事实都若无其事地躺在编年史里。看出一个
主题散落在三份档案中、哪份都没有核心。为决策编年史补上带精确出处
引文的记录，并且什么都不编造。

我们不止一次认真地把这些交给本地模型。结果很稳定：要么是空洞的修改，
要么是自信的错误。不是「稍差一点」——而是无法验收的工作：一次错误的
图谱修改会永久且无声地污染记忆。

对比一下：强云端模型的一次夜间复审，跨越图谱的 74 个核心主题，产出
了八千字的报告——矛盾、过时事实、可合并项、丢失的线索、三个真实
风险。全部带引文、全部可验证。本地模型撑不住这一类任务——是完全
撑不住，不是边缘略差。

## 为什么这是结构性的，而不是「再等半年」

两类任务的差别在于答案空间的大小与视野的长度。

窄任务的空间很小：是或否，五个标签选一个。错误代价低，且会被流水线
的下一环节抓住。这正是我们 4 GB 分类器能稳住 92% 的原因——任务与
模型的尺寸匹配。

图谱维护是长视野：几百个文件、交叉链接、几十条必须同时成立的约束
（「别碰别人的章节」「每条事实要有出处」「什么都不许编」）。在这里，
小模型的崩塌不是因为缺知识，而是缺工作记忆和守规矩的纪律。业界专门为此
建立了长记忆基准（LoCoMo、LongMemEval）不是没有原因的：记忆整合不是
把模型对准它就能解决的事——它需要被单独度量、单独搭脚手架。

新的本地模型每个月都在发布，窄任务上的差距已经关闭。综合任务上的
差距没有。我们说「暂时」——但明白这个「暂时」是任务类别的属性，
不是发布日历的属性。

## 我们的回应

按任务类别分工，而不是按意识形态。

**默认本地：** 音频、识别、声音、要点、纪要、分类、搜索、从新会议
提取节点。这是流水线——它每天运转，不需要任何人的许可。有一个例外
是有意为之：装不下大模型的机器可以把聊天部分——提示、要点、纪要——
交给云端网关（`llm.engine: cloud`），需要两个开关，并同样受总开关
约束。识别、声音、向量与 NLI 无论用哪个引擎都留在本地。

**强模型，严格 opt-in：** 核心复审、纪要与逐字稿的交叉核对、对本地
模型生成的主题档案做第二遍审阅。这些是少量、昂贵、聪明的操作——一晚
一次，不是一分钟一次。

关键在于云端接缝周围的「不信任工程」：

- 唯一决策点（`src/privacy.py`），fail-closed：配置里任何含糊都读作
  「不行」；
- 一个环境变量的 kill switch（`CHAROITE_NO_CLOUD`），一次静默全部
  云端，聊天网关也包括在内；
- 云端看到的是图谱，不是磁盘：它的工具被锚定在图谱文件夹内，因此
  `transcripts/` 文件夹、录音、日志、配置和项目的 git 历史都够不着。边界就是
  你授权的图谱——图谱里保存的逐字稿副本在其中可读，但写入被禁止；
- 修改图谱的权限是独立开关，默认关闭——云端在副本上工作，只有允许的
  改动才会搬回，并带图谱备份、修改边界和超时；
- Claude 层只通过订阅制 CLI 运行，API 密钥永远从它的环境中剔除：不会
  背着你按 token 计费。唯一带密钥的路径是上面那个 opt-in 的聊天
  网关——它的密钥放在单独的文件里，从不写进配置，且只走 https；
- 每条规则都由结构化测试钉死：测试直接读源码，任何削弱尝试都会
  让它变红。

在这里，隐私是架构的属性，不是落地页上的一段话。

## 什么会让我们改变主意

没有可否证标准的宣言只是广告。我们的标准：在自己的档案上维护基准，
每个值得注意的本地模型都跑一遍——`scripts/memory_bench.py`（档案上的
标准问题集，每晚运行）和 `scripts/bench_extract.py`（模型从真实会议
中往图谱里提取了什么，每条引文都对照逐字稿核验）。复审任务本身还没有
基准：在同一批核心上把本地模型的报告与云端报告并排比较，是下一个要
建的。当某个本地模型以云端水准撑住这项任务的那天，云端接缝用一行配置
即可关闭——代码本来就是这样构建的。

在那天之前，我们直说：local-first 的意思是「默认本地、隐私源于构造」。
它不意味着「永远不用任何云」——它意味着边界被显式划出、被测试守护、
在源码里对所有人可见。

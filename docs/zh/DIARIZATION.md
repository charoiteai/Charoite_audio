# 说话人分离配置

*[English](../DIARIZATION.md) · [Русский](../ru/DIARIZATION.md) · **中文***

Charoite 采用两遍说话人分离：

1. **实时**（会议进行中）：说话人嵌入模型实时把音频块标注为 «Собеседник 1/2/…»（“对话者 1/2/…”）。需要 ONNX 格式的 ERes2Net 嵌入模型，放在 `models/diar/embedding.onnx`（512 维输出，16 kHz 输入）。可从 [3D-Speaker 项目](https://github.com/modelscope/3D-Speaker)获取（在 CN-Celeb/VoxCeleb 上训练的 ERes2Net 对俄语和英语效果良好），一条命令即可安装：

   **最简单的方式——应用首次运行向导里的「区分说话人」按钮。** 终端里的等价
   做法见下。

   ```bash
   .venv/bin/python scripts/get_models.py --diar          # 默认模型
   .venv/bin/python scripts/get_models.py --diar --list   # 还有哪些可选
   .venv/bin/python scripts/get_models.py --diar --check  # 检查已安装的模型
   ```

   脚本会在连接前打印地址，校验下载的确实是 ONNX 且没有被截断，并放到守护进程查找的位置。模型来自 [3D-Speaker 项目](https://github.com/modelscope/3D-Speaker)（Apache-2.0），ONNX 镜像为 sherpa-onnx 整理。自定义链接用 `--url`。

   除可选云层之外，这是产品中唯一会联网的地方：只在你手动运行时联网，一次，之后完全离线；`--check` 完全不开连接。
2. **离线重跑**（按下停止后）：对完整录音按声道重新做说话人分离，过滤麦克风与系统音频之间的回声，把微小片段并入相邻片段，并由本地 LLM 根据对话中听到的名字给说话人命名。结果会替换实时生成的逐字稿草稿。

没有 `models/diar/embedding.onnx` 时 Charoite 仍能工作：改用声道标签（你 vs. 对方）代替按声音区分的标签。

调优（`config/config.yaml`）：

- `live_diarize_threshold`（默认 0.45）— 把音频块归到已知声音的余弦相似度阈值；不同人被合并成一个时调高，同一个人总被拆成两个时调低。

## 如何度量

「它老是分不清说话人」在拿出数字之前只是一种看法。`scripts/diar_bench.py`
计算 DER（说话人分离错误率）：被错误标注的语音时间占比——漏掉的语音、在静音
处听出的语音，以及归给错误声音的时间。假设标签会先与参考标签做匹配，因此
「spk0 而不是 Milena」不算错误：说话人分离要做的是区分人，而不是猜名字。

```bash
.venv/bin/python scripts/diar_bench.py --make    # 合成对话 + 标准答案
.venv/bin/python scripts/diar_bench.py           # 度量两个引擎
```

本仓库里没有会议录音，也不可能有——那是别人的谈话。测试样本在本地用 macOS
语音合成器生成：四个不同的声音朗读台词，标准答案是精确的，因为它由我们写下。
这是下限，不是基准：合成的声音比真实声音干净，没有串音，也没有房间噪声，因此
一个在这里都分不清说话人的引擎，在真实会议里只会更差。反过来则不成立——这些
数字绝不能被当作真实会议的质量来展示。

测于 2026-07-30（32 秒，4 个声音）：

| 引擎 | DER | 找到的声音 |
|---|---|---|
| 今天的实时模式（切分 + 按发言取嵌入） | **0.246** | 4 / 4 |
| 此前的分块跟踪器（`--engine live-legacy`） | 0.725 | 1 / 4 |
| 会后重跑（`--engine sherpa`） | 0.296 | 3 / 4 |
| 同上，但告知共有 4 个说话人 | 0.248 | 4 / 4 |

此前的跟踪器把所有人塌缩成了一个声音，而阈值几乎不起作用：从 0.25 到 0.55
结果完全一致。原因不在阈值，而在于语音是按计时器（三秒一块）切开的，而不是
在发言边界切开：一个块里装着上一句的结尾和下一句的开头，嵌入自然是混的。切分
给出边界，嵌入则按每次发言计算。

自 2026-08-15 起，识别同样按片段进行——位置化切分（`SegmentTracker.split`）。
当一个块里有几个人各说了至少一秒时，守护进程分别识别各个片段，每段得到自己的
作者；发言边界上的文字不再流向别人的声音。三条规则防止「微标签」：不足一秒的
他人片段不归属任何人（丢掉半秒的「对」比伪造作者更诚实——会后处理的短碎片
规则）、同一声音的相邻片段合并为一个窗口、窗口两端的余量不越过与他人语音间隙
的中点。被块右边界截断、且完全位于重叠区内的片段会被暂扣——下一个块会完整
带来它。

在同一夹具上用生产切法重测（块 3.0 秒、步长 2.5 秒，`--overlap` ——旧基准
首尾相接地切，结果偏乐观）：

| 实时模式 | DER | 混淆 | 声音数 |
|---|---|---|---|
| 每块一个标签（`--engine live`） | 0.270 | 0.162 | 4 / 4 |
| 位置化切分（`--engine live-split`） | **0.167** | **0.054** | 4 / 4 |

两种模式下说话人切换次数相同——转写并未闪烁。


## 合并阈值来自实测，而非拍脑袋

同一个人的话音常被分段切成几个簇——尤其是单麦克风录制的线下会议：人转过头、
往后靠、压低声音。合并步骤按余弦比较各簇的平均嵌入向量，把相近的并起来。

8 月 14 日在真实录音上实测了阈值：65 分钟、一支麦克风、三位讲话人。大簇之间的
两两相似度分得干干净净：

| 比较对象 | 相似度 |
|---|---|
| 同一嗓音的片段 | 0.68 – 0.89 |
| 不同的人 | 0.11 – 0.46 |

0.46 与 0.68 之间是一片空档，界线就该落在那里。此前的 **0.72 落在了「同一个人」
区间之内**：相似度 0.68 的一对永远合不到一起，于是一个人以两个「对话者」的身份
进入逐字稿。现在阈值是 **0.60**，两侧都有余量。

**安静的簇单独处理。** 「嗯」「对」这类应答信号很短，由此得到的嵌入向量噪声大，
够不到主阈值。这类簇按说话量一眼可辨：同一场会议中三位参与者占了 92% 的文本，
而十三个碎片各自只有一两秒——相差两个数量级。因此说话总量不足 **30 秒**的簇不算
独立参与者，会以更宽松的 **0.50** 归入最接近的嗓音——该值高于陌生人的上限，以免
把别人的发言算到参与者头上。

**合并根本看不见的簇。** 提取嵌入向量至少需要一秒连续语音。没有这样一段的簇不会
与任何人比较——再怎么调阈值也够不着，因为压根无从比起。同一段录音里，74 个簇中有
**8 个**属于此类：它们加起来只说了 1432 秒中的 6.9 秒（占 0.5%），通常只是一句
0.6–1.0 秒的应答。真人参与者不会只有这么点，可它们制造的标签却和真人一样多。

这类簇会并入**一个共用嗓音**，而不是分摊给各位参与者。究竟是谁说的「对」，我们并不
知道；硬算到某个人头上就是张冠李戴。共用标签老实地表示：短应答，嗓音未识别。

合并绝不会做的事：不会把两位都达到说话量下限的人并起来，无论他们多像；也不会把
与在场任何人都不像的碎片强行归属。多一个标签，也比张冠李戴诚实。

# 隐私

*[English](../../PRIVACY.md) · [Русский](../ru/PRIVACY.md) · [**中文**]*

Charoite 按 local-first 原则构建。具体而言：

- **零遥测。** 没有任何分析、崩溃上报或「匿名使用统计」。可以 grep 代码验证。
- **除您自己在 localhost 运行的服务外无任何网络调用**（Ollama 在 `127.0.0.1:11434`、可选的本地 STT 流服务）——除非您明确开启云层。有两个例外并不属于云层，我们在此明确写出而非隐藏：**每日版本检查**（请求 `api.github.com`，默认开启，可用 `check_updates: false` 关闭；不会发送关于您的任何内容，但请求本身会暴露您的 IP 和使用 Charoite 这一事实），以及首次识别时的**一次性模型下载**（来自 Hugging Face 或 `scripts/get_models.py` 中的镜像）。两者都遵守总开关：设置 `CHAROITE_NO_CLOUD=1` 后，版本检查会被跳过，模型下载会被直接拒绝，而不是在会议进行中悄悄联网。LLM 地址由代码守护，而非约定：所有读取方都从 `src/privacy.py` 获取地址，非回环的 `llm.base_url`（另一台机器、云端端点）会在启动时被拒绝，除非显式设置 `llm.allow_remote: true` —— 逐字稿会发往该地址，把它指向别处是一个隐私决定，而不是调优旋钮。
- **应用内遵循同一规则。**「设置」中的 Ollama 字段过去接受任意地址并绕过 `privacy.py` 发送请求——承诺只由两层中的一层守护，而语义索引分块（整个会议归档）和实时逐字稿都走这条路径。自 0.48.0 起，应用的判断与守护进程一致：回环地址始终放行，其他地址仅在显式设置 `llm.allow_remote: true` 时放行，且在总开关下永不放行。被拒绝的地址不会被静默替换：设置中会显示该地址与原因，请求转为发往 `localhost`。
- **云层为 opt-in，默认关闭。** 开关恰好五个，在随附配置中全部为 `false`，且这份清单就是全部真相：若出现第五个而未在此记录，测试会失败。
  - `cloud_enrich` —— 会议停止后，**完整逐字稿**送往 Claude 做复盘。同一开关也授权**夜间图谱审阅**：核心审阅（最多 6 万字符的核心内容）与档案审阅会在夜里把从图谱汇集的文本发送到 Anthropic。
  - `cloud_live` —— 会议进行中的提问以**逐字稿片段**发出，每个问题一次请求。
  - `cloud_engine` —— **整个对话交由云端模型**（`llm.engine: cloud`）：提示、要点、思路线索与会议纪要不再由本地模型计算，而是交给外部 OpenAI 兼容网关。与其他开关的区别在于数据量：它们偶尔发送片段，而它在会议期间持续发送整段对话流，会后处理时还会发送逐字稿文本。需要地址（`llm.cloud_base_url`，仅限 https）与放在单独文件中的密钥（`llm.cloud_key_file`，绝不写入配置）。二者缺一不可：只有地址而无许可，或只有许可而无地址，都会继续使用本地模型。断网时若已安装本地模型则由其作答（`llm.cloud_fallback_local`），并会在 err 日志中留下一行说明。无论开关如何，语音识别、说话人分离、检索向量与 NLI 都留在本机。
  - `cloud_hints` —— 云端润色提示：**每次提示**都会发送逐字稿，也就是在整场会议期间持续成流，而非一次性打包。同时需要开启 `cloud_live`。
  - `cloud_edit_graph` —— 唯一授予**写入而非发送**的开关：会后复盘可以直接改写图谱文件，而不只是写一份报告（夜间档案复核仍是纯文本：模型返回文本，文件由 Charoite 写入）。同时需要开启 `cloud_enrich`。逐字稿、会议纪要、会议归档文件夹与「## 作者修改」永不触碰，每次修改前都会备份。这由代码保证，而非提示词的措辞。云端复盘不在图谱里工作，而在图谱的**副本**中：
工作进程在运行前制作两份副本（作为基准的快照，以及沙箱），并把 CLI 的工作目录
指向沙箱。沙箱与快照之间的一切差异都出自云端——作者身份由结构决定，而非靠猜测。
拿到回答后，工作进程在图谱锁下把云端的修改搬入真正的图谱：允许的写入，越界的
（受保护文件夹、隐藏路径、作者段落）送入隔离区；在此期间被产品自己改动过的文件
保持原样——实时工作优先，云端的版本进入隔离区。删除与重命名一概不搬运：「移除」
节点唯一被接受的形式是重定向占位（`# 名称 → [[文件夹/正本]]`），与 tier3 合并
重复节点后留下的一致。无效的回答（超时、非零退出码、片段而非复盘）无需回滚：
图谱一个字节都没有变动，沙箱直接丢弃，其中的修改进入隔离区供人查看。运行前
工作进程还会向 CLI 交付一份明确的写入禁止清单：受保护文件夹、每一个隐藏文件夹
与文件、每一个符号链接——CLI 会直接拒绝这些路径，搬运比对是第二道防线。任何内容
都不会被直接删除：未获搬运的一切都留在快照旁的隔离区（`backups/<图谱>-<哈希>/
cloud_quarantine/<逐字稿文件名>-<时间>/`，保留最近十次运行）。Obsidian 自身的
实时状态（`.obsidian/` 下的窗口布局、设置、插件 `data.json`）由结构本身隔离在
射程之外——那是 Obsidian 写入图谱，而非云端写入沙箱。同一图谱同一时间只有一个
工作进程：快照旁的锁让会后复盘依次进行，第二个进程等待，若第一个在超时内未结束，
则以只读方式运行。图谱之外的文件在更早一层、由 CLI 自身的权限规则挡住：复盘只看到
显式工具（`Read`、`Grep`、`Glob`，开启开关后再加 `Edit`/`Write`），`Read(/**)`
与可选的 `Edit(/**)` 锚定在工作目录，`dontAsk` 会拒绝其之外的任何路径而不是询问，
Shell、网络与 MCP 工具一概不可用。若图谱未配置、是 `/` 或家目录，调用退化为纯文本，
而不会回退到访问 `transcripts/` 中的文件。注意：图谱本身保存着流水线放入 `Документация/Стенограммы встреч` 的历史逐字稿副本，以及 `.cloud_backup/`（旧位置）以及新的快照目录 `backups/<图谱>-<哈希>/cloud_backup/`（位于守护进程数据旁，不参与同步；2026-08-21 迁移） 中的图谱快照——为查找交叉链接而读取图谱，也就意味着复盘可以读到它们；信任边界是你已经向产品开放的图谱，而不是代码仓库。图谱之外的文件在更早一层、由 CLI 自身的权限规则挡住：复盘只看到显式工具（`Read`、`Grep`、`Glob`，开启开关后再加 `Edit`/`Write`），`Read(/**)` 与可选的 `Edit(/**)` 锚定在 `cwd=graph`，`dontAsk` 会拒绝图谱以外的任何路径而不是询问，Shell、网络与 MCP 工具一概不可用。若图谱未配置、是 `/` 或家目录，调用退化为纯文本，而不会回退到访问 `transcripts/` 中的文件。

  开启后它们在您自己的订阅下运行 `claude` CLI；您选择送出的内容会以您的账号、按 Anthropic 的条款发送。全部关掉，Charoite 即完全离线。
- **由一处决定，检查设在请求离开机器的地方。** 每个「这能离开本机吗？」的问题都由 `src/privacy.py` 回答。检查位于网络出口本身，而不只在调用方。配置中的沉默意味着「否」：缺失的键、`"false"`、`0`、空值永远不会被当作许可。`tests/test_privacy_defaults.py` 和 `tests/test_cloud_call_sites.py` 守护这两条性质——这一条不是承诺，是测试。
- **总开关。** 环境变量 `CHAROITE_NO_CLOUD=1`（或历史名称 `SUFLER_NO_CLOUD=1`）强制关闭云层，无论配置写了什么：「这一次严格离线」应该是环境变量，而不是别人会议前手改 YAML。它同样压过 `llm.allow_remote`：开关生效时，非本机的 `llm.base_url` 也会被拒绝——「这台机器不外发任何东西」就是字面意思。
- **只有你的账户能读会议内容。** 录音、逐字稿、纪要、检索索引和守护进程日志只为所有者创建——文件 `0600`，目录 `0700`。在 0.50 之前它们使用默认掩码（`0644`/`0755`）写入，同一台 Mac 上的任何第二个账户都能读取全部会议，无需征求任何许可。已有安装会在守护进程下次启动时迁移，而 `tests/test_private_permissions.py` 会在新入口忘记设置掩码时失败。它覆盖不到的：你同步到别处的副本（iCloud、Time Machine）遵循那些服务的规则，机器管理员始终能读取你的文件。
- **录音是临时的。** 完整会议音频只为会后精确重建逐字稿而保留，`record_keep_days` 天后删除（默认 2 天）。清理在守护进程启动时执行，而不仅在新会议开始时——即使一周未录音或关闭了 `record`，录音也会按期过期。
- **可以彻底忘掉一场会议。** `record_keep_days` 只管音频，`scripts/forget_meeting.py <日期|时间戳>` 管其余全部（导入会议在导入文件夹 `done/` 中的音频副本会随之删除——前提是应用以 `--import-folder` 传入该文件夹；从命令行不带它时，计划会明说，副本稍后由清理删除）：逐字稿及其派生文件、归档中的会议文件夹、会议节点、「文档」下的逐字稿副本、内核中的编年行（连同那场会议带来的事实一起）、档案与人物节点中的链接、`logs/meeting-status/` 中的处理状态和该会议的图谱/云端复核日志、复制到「文档」下的全部 `<时间戳>_*.md` 产物（不只是裸逐字稿），以及会前快照里那场会议的文件——图谱里旧的 `.cloud_backup/` 和它们的新家 `backups/<图谱>-<哈希>/cloud_backup/`（在守护进程数据旁，位于同步的 vault 之外，21.08 迁移）：云端复核改图前的快照会整体复制图谱，遗忘必须触及这些副本——还有会后复盘的隔离区（`backups/<图谱>-<哈希>/cloud_quarantine/`：该会议那次运行的目录整体删除，其他运行中带有该时间戳的文件也一并删除）。默认只打印计划——删除不可逆，需要 `--yes`；对保留节点的修改会备份到 `.forget_backup/`。它做不到的：取回已同步到 iCloud 或 Time Machine 的副本，以及清理其他参会者手里的文件。构建图谱时，会议的主题行和决定会以会议键发送到记忆伴侣（`brain`，`127.0.0.1:8100`，`/remember`）；遗忘会用同一个键调用它的 `/forget`（23.08 之前没有键的事实按文本查找），记忆服务关闭时会打印如何重试；重命名会议也会同步到那里（`/rename`）。还有一处它会明说而不是假装：本地聊天（Application Support 下的 `chat_history.json`：对话的最近 200 条消息——回答可能复述图谱，图谱片段本身只进入提示词，不会写入该文件）只能用聊天自己的**清除**按钮清理——遗忘一场会议不会改写它。
- **iPhone 伴侣应用保留最近五条已发送录音。** 已送达的文件从队列移到 `sent/`，最新的五条会留在那里，直到被更新的挤出——这是送达失败时的保险，不是归档。想更早删除：在“文件”里删除应用文档，或删除应用本身。
- **导入的音频同样会过期。** `scripts/import_meeting.py` 会把源文件的副本放入会议文件夹（`Исходник.*`）以便重建逐字稿，并把处理完的原件移入导入文件夹的 `done/`。两份音频副本都会在导入后 `audio.import_keep_days`（默认 2 天，与 `record_keep_days` 无关）删除——清理在每次扫描后以及应用运行期间每六小时执行，「外部录音」标签页会在每个文件旁显示日期。文本与字幕源（txt/md/vtt/srt）不是音频，会留在归档中。导入失败的文件绝不会被删除：它带着错误标记留在导入文件夹里，直到你重试或移走它。拖入标签页的文件是副本，你的原件不会被触碰。在此规则之前进入 `done/` 的副本从第一次看到它们的清理起计算天数。
- **模型只下载一次。** 首次运行时会从 Hugging Face 获取所选的 STT 模型；说话人分离模型由 `scripts/get_models.py --diar` 手动安装，该命令会在连接前打印地址。之后全部在本地运行：守护进程和应用都不会再去下载模型。若需要完全不联网的机器，请预先把模型放入 `models/` 再离线运行。
- **不保存声纹。** 实时说话人分离只在会议进行期间将声纹向量保存在内存中。任何声音衍生数据都不写入磁盘。
- **您的数据就是普通文件。** 逐字稿、摘要和知识图谱都是您所选文件夹中的 Markdown。删除、同步、加密——都由您做主。

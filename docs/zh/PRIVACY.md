# 隐私

*[English](../../PRIVACY.md) · [Русский](../ru/PRIVACY.md) · [**中文**]*

Charoite 按 local-first 原则构建。具体而言：

- **零遥测。** 没有任何分析、崩溃上报或「匿名使用统计」。可以 grep 代码验证。
- **除您自己在 localhost 运行的服务外无任何网络调用**（Ollama 在 `127.0.0.1:11434`、可选的本地 STT 流服务）——除非您明确开启云层。LLM 地址由代码守护，而非约定：所有读取方都从 `src/privacy.py` 获取地址，非回环的 `llm.base_url`（另一台机器、云端端点）会在启动时被拒绝，除非显式设置 `llm.allow_remote: true` —— 逐字稿会发往该地址，把它指向别处是一个隐私决定，而不是调优旋钮。
- **应用内遵循同一规则。**「设置」中的 Ollama 字段过去接受任意地址并绕过 `privacy.py` 发送请求——承诺只由两层中的一层守护，而语义索引分块（整个会议归档）和实时逐字稿都走这条路径。自 0.48.0 起，应用的判断与守护进程一致：回环地址始终放行，其他地址仅在显式设置 `llm.allow_remote: true` 时放行，且在总开关下永不放行。被拒绝的地址不会被静默替换：设置中会显示该地址与原因，请求转为发往 `localhost`。
- **云层为 opt-in，默认关闭。** 开关恰好四个，在随附配置中全部为 `false`，且这份清单就是全部真相：若出现第五个而未在此记录，测试会失败。
  - `cloud_enrich` —— 会议停止后，**完整逐字稿**送往 Claude 做复盘。
  - `cloud_live` —— 会议进行中的提问以**逐字稿片段**发出，每个问题一次请求。
  - `cloud_hints` —— 云端润色提示：**每次提示**都会发送逐字稿，也就是在整场会议期间持续成流，而非一次性打包。同时需要开启 `cloud_live`。
  - `cloud_edit_graph` —— 唯一授予**写入而非发送**的开关：夜间档案复核与会后复盘可直接改写图谱，而不只是生成报告；同时需要开启 `cloud_enrich`。关闭时复盘只看到 `Read`、`Grep`、`Glob`，开启时才增加 `Edit`、`Write`。这些不是全局权限：Claude CLI 将 `Read(/**)` 与可选的 `Edit(/**)` 锚定到 `cwd=graph`，`dontAsk` 拒绝图谱外的任何路径，Shell、网络和 MCP 工具均不可用；符号链接及其目标都必须留在允许范围内。若图谱不存在、指向 `/` 或用户主目录，调用会退化为纯文本模式，而不会给 `transcripts/` 目录文件权限。本次会议文件由 Charoite 直接放入请求；模型可读取已配置图谱以查找关联，但项目逐字稿、录音、日志、`.git`、`config/config.yaml` 以及图谱外的其他用户文件均不可达。逐字稿、会议纪要、会议归档文件夹与「## 作者修改」永不被修改，每次图谱编辑前都会备份；工作进程运行后逐一比对并撤销越界改动。截断的复盘只保存为 `.partial`，不会冒充成品。

  开启后它们在您自己的订阅下运行 `claude` CLI；您选择送出的内容会以您的账号、按 Anthropic 的条款发送。全部关掉，Charoite 即完全离线。
- **由一处决定，检查设在请求离开机器的地方。** 每个「这能离开本机吗？」的问题都由 `src/privacy.py` 回答。检查位于网络出口本身，而不只在调用方。配置中的沉默意味着「否」：缺失的键、`"false"`、`0`、空值永远不会被当作许可。`tests/test_privacy_defaults.py` 和 `tests/test_cloud_call_sites.py` 守护这两条性质——这一条不是承诺，是测试。
- **总开关。** 环境变量 `CHAROITE_NO_CLOUD=1`（或历史名称 `SUFLER_NO_CLOUD=1`）强制关闭云层，无论配置写了什么：「这一次严格离线」应该是环境变量，而不是别人会议前手改 YAML。它同样压过 `llm.allow_remote`：开关生效时，非本机的 `llm.base_url` 也会被拒绝——「这台机器不外发任何东西」就是字面意思。
- **录音是临时的。** 完整会议音频只为会后精确重建逐字稿而保留，`record_keep_days` 天后删除（默认 2 天）。清理在守护进程启动时执行，而不仅在新会议开始时——即使一周未录音或关闭了 `record`，录音也会按期过期。
- **可以彻底忘掉一场会议。** `record_keep_days` 只管音频，`scripts/forget_meeting.py <日期|时间戳>` 管其余全部：逐字稿及其派生文件、归档中的会议文件夹、会议节点、「文档」下的逐字稿副本、内核中的编年行（连同那场会议带来的事实一起）、档案与人物节点中的链接，以及 `.cloud_backup/` 里那场会议的文件——云端复核改图前的快照会整体复制图谱，遗忘必须触及这些副本。默认只打印计划——删除不可逆，需要 `--yes`；对保留节点的修改会备份到 `.forget_backup/`。它做不到的：取回已同步到 iCloud 或 Time Machine 的副本，以及清理其他参会者手里的文件。
- **导入图谱的音频由你自行管理。** `scripts/import_meeting.py` 会把源文件复制到会议文件夹，以便日后重建逐字稿。该副本位于图谱中（通常在 iCloud），**不受** `record_keep_days` 约束——如需删除，请删除整个会议文件夹。
- **模型只下载一次。** 首次运行时会从 Hugging Face 获取所选的 STT 模型；说话人分离模型由 `scripts/get_models.py --diar` 手动安装，该命令会在连接前打印地址。之后全部在本地运行：守护进程和应用都不会再去下载模型。若需要完全不联网的机器，请预先把模型放入 `models/` 再离线运行。
- **不保存声纹。** 实时说话人分离只在会议进行期间将声纹向量保存在内存中。任何声音衍生数据都不写入磁盘。
- **您的数据就是普通文件。** 逐字稿、摘要和知识图谱都是您所选文件夹中的 Markdown。删除、同步、加密——都由您做主。

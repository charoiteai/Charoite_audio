# 隐私

*[English](../../PRIVACY.md) · [Русский](../ru/PRIVACY.md) · [**中文**]*

Charoite 按 local-first 原则构建。具体而言：

- **零遥测。** 没有任何分析、崩溃上报或「匿名使用统计」。可以 grep 代码验证。
- **除您自己在 localhost 运行的服务外无任何网络调用**（Ollama 在 `127.0.0.1:11434`、可选的本地 STT 流服务）——除非您明确开启云层。有两个例外并不属于云层，我们在此明确写出而非隐藏：**每日版本检查**（请求 `api.github.com`，默认开启，可用 `check_updates: false` 关闭；不会发送关于您的任何内容，但请求本身会暴露您的 IP 和使用 Charoite 这一事实），以及首次识别时的**一次性模型下载**（来自 Hugging Face 或 `scripts/get_models.py` 中的镜像）。两者都遵守总开关：设置 `CHAROITE_NO_CLOUD=1` 后，版本检查会被跳过，模型下载会被直接拒绝，而不是在会议进行中悄悄联网。LLM 地址由代码守护，而非约定：所有读取方都从 `src/privacy.py` 获取地址，非回环的 `llm.base_url`（另一台机器、云端端点）会在启动时被拒绝，除非显式设置 `llm.allow_remote: true` —— 逐字稿会发往该地址，把它指向别处是一个隐私决定，而不是调优旋钮。
- **应用内遵循同一规则。**「设置」中的 Ollama 字段过去接受任意地址并绕过 `privacy.py` 发送请求——承诺只由两层中的一层守护，而语义索引分块（整个会议归档）和实时逐字稿都走这条路径。自 0.48.0 起，应用的判断与守护进程一致：回环地址始终放行，其他地址仅在显式设置 `llm.allow_remote: true` 时放行，且在总开关下永不放行。被拒绝的地址不会被静默替换：设置中会显示该地址与原因，请求转为发往 `localhost`。
- **云层为 opt-in，默认关闭。** 开关恰好四个，在随附配置中全部为 `false`，且这份清单就是全部真相：若出现第五个而未在此记录，测试会失败。
  - `cloud_enrich` —— 会议停止后，**完整逐字稿**送往 Claude 做复盘。同一开关也授权**夜间图谱审阅**：核心审阅（最多 6 万字符的核心内容）与档案审阅会在夜里把从图谱汇集的文本发送到 Anthropic。
  - `cloud_live` —— 会议进行中的提问以**逐字稿片段**发出，每个问题一次请求。
  - `cloud_hints` —— 云端润色提示：**每次提示**都会发送逐字稿，也就是在整场会议期间持续成流，而非一次性打包。同时需要开启 `cloud_live`。
  - `cloud_edit_graph` —— 唯一授予**写入而非发送**的开关：会后复盘可以直接改写图谱文件，而不只是写一份报告（夜间档案复核仍是纯文本：模型返回文本，文件由 Charoite 写入）。同时需要开启 `cloud_enrich`。逐字稿、会议纪要、会议归档文件夹与「## 作者修改」永不触碰，每次修改前都会备份。这由代码保证，而非提示词的措辞：工作进程在运行前对整个图谱做快照（每个文件，不只是 Markdown），运行后逐一比对，撤销一切越界改动——无论是被修改、被删除，还是在受保护位置（逐字稿副本、归档文件夹、隐藏的快照文件夹、作者段落）新建的文件。注意：图谱本身保存着流水线放入 `Документация/Стенограммы встреч` 的历史逐字稿副本，以及 `.cloud_backup/`（旧位置）以及新的快照目录 `backups/<图谱>-<哈希>/cloud_backup/`（位于守护进程数据旁，不参与同步；2026-08-21 迁移） 中的图谱快照——为查找交叉链接而读取图谱，也就意味着复盘可以读到它们；信任边界是你已经向产品开放的图谱，而不是代码仓库。图谱之外的文件在更早一层、由 CLI 自身的权限规则挡住：复盘只看到显式工具（`Read`、`Grep`、`Glob`，开启开关后再加 `Edit`/`Write`），`Read(/**)` 与可选的 `Edit(/**)` 锚定在 `cwd=graph`，`dontAsk` 会拒绝图谱以外的任何路径而不是询问，Shell、网络与 MCP 工具一概不可用。若图谱未配置、是 `/` 或家目录，调用退化为纯文本，而不会回退到访问 `transcripts/` 中的文件。

  开启后它们在您自己的订阅下运行 `claude` CLI；您选择送出的内容会以您的账号、按 Anthropic 的条款发送。全部关掉，Charoite 即完全离线。
- **由一处决定，检查设在请求离开机器的地方。** 每个「这能离开本机吗？」的问题都由 `src/privacy.py` 回答。检查位于网络出口本身，而不只在调用方。配置中的沉默意味着「否」：缺失的键、`"false"`、`0`、空值永远不会被当作许可。`tests/test_privacy_defaults.py` 和 `tests/test_cloud_call_sites.py` 守护这两条性质——这一条不是承诺，是测试。
- **总开关。** 环境变量 `CHAROITE_NO_CLOUD=1`（或历史名称 `SUFLER_NO_CLOUD=1`）强制关闭云层，无论配置写了什么：「这一次严格离线」应该是环境变量，而不是别人会议前手改 YAML。它同样压过 `llm.allow_remote`：开关生效时，非本机的 `llm.base_url` 也会被拒绝——「这台机器不外发任何东西」就是字面意思。
- **只有你的账户能读会议内容。** 录音、逐字稿、纪要、检索索引和守护进程日志只为所有者创建——文件 `0600`，目录 `0700`。在 0.50 之前它们使用默认掩码（`0644`/`0755`）写入，同一台 Mac 上的任何第二个账户都能读取全部会议，无需征求任何许可。已有安装会在守护进程下次启动时迁移，而 `tests/test_private_permissions.py` 会在新入口忘记设置掩码时失败。它覆盖不到的：你同步到别处的副本（iCloud、Time Machine）遵循那些服务的规则，机器管理员始终能读取你的文件。
- **录音是临时的。** 完整会议音频只为会后精确重建逐字稿而保留，`record_keep_days` 天后删除（默认 2 天）。清理在守护进程启动时执行，而不仅在新会议开始时——即使一周未录音或关闭了 `record`，录音也会按期过期。
- **可以彻底忘掉一场会议。** `record_keep_days` 只管音频，`scripts/forget_meeting.py <日期|时间戳>` 管其余全部：逐字稿及其派生文件、归档中的会议文件夹、会议节点、「文档」下的逐字稿副本、内核中的编年行（连同那场会议带来的事实一起）、档案与人物节点中的链接、`logs/meeting-status/` 中的处理状态和该会议的图谱/云端复核日志、复制到「文档」下的全部 `<时间戳>_*.md` 产物（不只是裸逐字稿），以及 `.cloud_backup/` 里那场会议的文件——云端复核改图前的快照会整体复制图谱，遗忘必须触及这些副本。默认只打印计划——删除不可逆，需要 `--yes`；对保留节点的修改会备份到 `.forget_backup/`。它做不到的：取回已同步到 iCloud 或 Time Machine 的副本，以及清理其他参会者手里的文件。还有两处它会明说而不是假装：构建图谱时，会议的主题行和决定会发送到记忆伴侣（`brain`，`127.0.0.1:8100`，`/remember`），而该服务目前还没有遗忘功能——计划里会写明；本地聊天（Application Support 下的 `chat_history.json`，最近 200 条消息及其引用的图谱片段）只能用聊天自己的**清除**按钮清理——遗忘一场会议不会改写它。
- **iPhone 伴侣应用保留最近五条已发送录音。** 已送达的文件从队列移到 `sent/`，最新的五条会留在那里，直到被更新的挤出——这是送达失败时的保险，不是归档。想更早删除：在“文件”里删除应用文档，或删除应用本身。
- **导入图谱的音频由你自行管理。** `scripts/import_meeting.py` 会把源文件复制到会议文件夹，以便日后重建逐字稿。该副本位于图谱中（通常在 iCloud），**不受** `record_keep_days` 约束——如需删除，请删除整个会议文件夹。
- **模型只下载一次。** 首次运行时会从 Hugging Face 获取所选的 STT 模型；说话人分离模型由 `scripts/get_models.py --diar` 手动安装，该命令会在连接前打印地址。之后全部在本地运行：守护进程和应用都不会再去下载模型。若需要完全不联网的机器，请预先把模型放入 `models/` 再离线运行。
- **不保存声纹。** 实时说话人分离只在会议进行期间将声纹向量保存在内存中。任何声音衍生数据都不写入磁盘。
- **您的数据就是普通文件。** 逐字稿、摘要和知识图谱都是您所选文件夹中的 Markdown。删除、同步、加密——都由您做主。

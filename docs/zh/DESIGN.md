# Charoite 设计系统

*[English](../DESIGN.md) · [Русский](../ru/DESIGN.md) · **中文***

两个平台，同一个性格：macOS 应用与 iPhone 伴侣应用由同一套设计令牌构建。代码中的权威来源是各 target 里的 `Theme.swift`（`app/Sources/CharoiteApp/Theme.swift`、`app-ios/Sources/CharoiteiOS/Theme.swift`）；在 macOS 上，`DesignKit.swift` 与 `CharoiteButton.swift` 为其补充表面、警示与按钮令牌。本文档是人类可读的描述及其背后的约定 — 以代码为准。Android 伴侣应用（`app-android/`）尚未改用这套令牌：它使用 Material 3 和自己的一对紫色（`#9B6DFF` / `#6C4BD8`）。

## 调色板

| 令牌 | 值 | 角色 |
|---|---|---|
| `accent` | `#6366F1` 靛蓝 | 操作：按钮、链接、激活状态 |
| `violet` | `#8B5CF6` 紫龙晶 | 性格：渐变、品牌点缀 |
| `brand` | accent→violet 渐变 | “活跃”操作：录音、首次运行 |
| `sky` | `#0EA5E9` | Claude — 会议中唯一离开本机的图层，与本地明确区分 |
| `ok` | `#059669` | 成功、绿色状态 |
| `warning` | 系统橙色 | 需要注意但没有损坏；`overdue`（逾期）是它的特例 |
| `danger` | `#DC2626` | 仅用于删除（危险按钮）：逾期是提醒，删除是销毁 |
| `surfaceMemory` | accent 5 % | 薰衣草色：会议脉络面板，提示与记忆回答都落在这里 |
| `surfaceCloud` / `borderCloud` | sky 6 % / 22 % | 离开本机的内容：Claude 卡片、云端档案开关 |

语义色（录音/错误的红色）用系统颜色，不属于品牌色。背景与文字使用平台的系统材质（`.bar`、`.background`、`secondary`）：深色模式无需额外适配，且始终保持真实。

颜色和字号从不“就地”设定：视图使用 `Theme.warning` 而不是 `.orange`，`Theme.ok` 而不是 `.green`，使用系统文字样式（`.caption`、`.callout`、`.headline`、`.title2`）而不是 `.system(size:)`。`tests/test_design_discipline.py` 遇到第一个例外就让测试失败：2026 年 8 月的审计发现了 21 处就地颜色和 13 处写死的字号，而只活在纸面上的体系一定会走样。

### 表面即来源

白色系统表面 — 此刻、本地。薰衣草色（`Theme.surfaceMemory`）— 记忆：会议界面上的脉络面板，提示以及来自档案与图谱的回答都落在这里。在「记忆」界面上，所有者选用了会议库的配色（8 月 24 日）：模型回答是带细边框的白色卡片，来源由来源标签和元信息行承载，而不是靠表面颜色；`MemorySurface` 容器已删除。天蓝色（`CloudSurface`）— 离开这台 Mac 的内容：会议界面上的 Claude 卡片、设置里的云端档案开关。“本地静默，云端可见”的原则由此变得看得见，而不只是写在纸上；颜色从不是唯一信号 — 每个云端表面也会用文字说明（“离开本机”）。设置里的「离开本机的内容」一节用文字列出每条外出路径；其中的云端对话开关与版本检查还没有放到天蓝色表面上 — 这是已知的缺口。

## 字体排印

使用平台系统字体（SF），不引入自定义字体：这款应用是伴随工作的工具，不是展示橱窗。

- 面板标题与大写标签：大写的 `caption2.semibold` + 字距 0.8，次要颜色（macOS 端为 DesignKit 的 `PaneHeader`，iOS 端为 `Theme.label`）。
- 录音计时器：等宽数字，行不会每秒跳动；计时器是主角的地方用细字重（iPhone 录音界面为 `thin`，`RecordCapsule` 里为 `light`），会议标题栏录音按钮旁用红色的 `headline`。
- 正文：系统字号；再长的俄语字符串也绝不挤压。

## 几何规格

- 圆角（`Theme.radius` / `Theme.radiusCard`）：输入框与小元素为 8；卡片与聊天气泡为 12；胶囊控件为药丸形。
- 内边距：面板内部默认 12，窗口边缘 14–16。
- 卡片：系统表面填充；阴影只给“活跃”元素（录音按钮），静态卡片一律不加。

## 组件

- **面板**：图标 + 大写标题 + 可选计数（DesignKit 的 `PaneHeader`），次要颜色，`.bar` 背景；复制按钮放在承载“要带走的结果”的面板上 — 会议脉络（提示与 Claude 的回答都落在这里）— 不放在原始逐字稿流上。
- **图层胶囊**：会议界面的图层（「提示」、Claude）是放在 `LayerBar` 里的 `LayerChip`，而不是系统开关 — 激活的图层为靛蓝填充，Claude 为 `sky` 描边，因为它是唯一离开本机的图层。同一种胶囊也在「记忆」界面上显示「图谱记忆」的状态。每个胶囊都向 VoiceOver 报告「已开启/已关闭」与选中状态，颜色不是唯一信号。
- **录音按钮**：`brand` 渐变加柔和的 accent 色阴影。形状因位置而异：「今天」页上是胶囊（`RecordCapsule`），会议标题栏里是按钮体系中 32 pt 的按钮（圆角 7），与相邻按钮齐平；在 Mac 上录音进行时改为系统红色，阴影关闭。iPhone 上是圆形，用渐变的径向版本（`Theme.record`）；录音时渐变保持不变，中间的白点变成停止方块。
- **空状态**（DesignKit 的 `EmptyState`）：一个标题、一行说明会出现什么，以及通往它的那一个操作，贴靠左上方；标题旁一个小图标，不用插画。
- **投递队列**（iPhone）：是一个入口，而不是一行灰字 — 显示数量，一旦有录音等待超过一天就变橙色；点开是一张列表，列出所有尚未送出的录音（类型、时间、大小），每条都可「分享」。语言平实，不弹警告框。
- **健康状态**（macOS 的 `HealthRollup`）：录音、处理、Ollama 与夜间任务汇总为一个状态，用于菜单栏图标和状态行。红色表示数据此刻正在丢失（会议中录音失败）；其余一律是 `warning`。问题会一直留在屏幕上，直到其所有者确认恢复 — 普通的状态行不会把它冲掉。
- **统一的按钮体系**（`CharoiteButton`，macOS）：七种角色——醒目、常规、安静、
  链接、危险、填充危险、图标——以及三种尺寸（s/m/l，高度 21/26/32 pt）。每个
  面板只放一个醒目按钮；不使用系统蓝（醒目用 `brand`，链接用 `accent`）；没有
  文字的按钮必须带 `.help` 和无障碍标签。按钮圆角跟随其高度，而不是上面的表面
  圆角：21 pt 的控件配 12 pt 圆角就成了胶囊，而不是按钮。完整规则与交付包见
  [BUTTONS_2026-08.md](../design/BUTTONS_2026-08.md)。
- **手机伴侣**（iPhone，2026 年 8 月）：录音、会议列表、会议卡片、任务与投递
  队列——与 Mac 上相同的令牌与规则，但不用 sky：伴侣只与 iCloud 文件夹交流。
  规范与原型见 [MOBILE_2026-08.md](../design/MOBILE_2026-08.md)；其中还包含修订中
  标为「未开始」的三个 macOS 界面——记忆、任务、会议库——三者都已在 8 月完成。
  在手机上，目前按原型实现的是录音界面和队列列表；会议列表、会议卡片与任务仍比
  原型简单（普通列表、由纪要生成且没有四种深度的卡片、没有汇总和「按期限」视图
  的任务）。

## 界面文案语气

语言鲜活，不带官腔套话。按钮点明操作，状态陈述结果，错误说明发生了什么、该怎么办。不使用“请”“抱歉”“已成功”这类词。

## 原则

1. 本地静默，云端可见：任何离开本机的东西都有自己的颜色（`sky`）和关闭开关。
2. 没有什么会无声消失：用队列与状态取代静默失败。
3. 不做声纹生物识别 — 设计上也如此体现：没有任何“声纹档案”界面。
4. 深色模式不是简单反色，而是同一套令牌配合系统材质。
